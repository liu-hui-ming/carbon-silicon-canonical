# 第054集｜模型安全核心术语体系全局锁定

模型安全核心术语体系，是整套法典001~053卷宗的统一语义基座。区别于零散注释、临时口头定义：零散定义随人员迭代、跨团队协作产生语义漂移；全局锁定术语体系，是对全卷宗内所有风险概念、层级、闸口、度量名词做唯一释义、边界切割、符号约束与版本哈希锚定；消除一词多义、同义异名，保障跨团队审计、红队、归档、跨卷宗引用语义完全对齐，属于法典底层语义确权层。
定义基准
模型安全核心术语体系（Globally Locked Terminology System for Model Safety）一套强约束、不可随意释义的标准化术语集合，包含唯一名词、定义、边界区分、关联关系、反例、风险层级映射；术语条目绑定唯一ID、归档哈希，纳入法典版本基线。全局锁定，不是永久禁止修订，而是任何术语新增、修改、删除必须走评审、版本升级、哈希重锚、全卷宗同步修订流程。风险核心：术语歧义会传导到测评、审计、台账、红队报告，造成同事件不同判定，整套安全治理体系在语义层面失准。
区分边界：
1. 术语体系锁定 ≠ 安全规则固化。安全规则是管控策略；术语体系是描述风险的语言。规则可以在术语不变前提下调整；术语一旦改动，所有卷宗、审计基线、数据集标签全部需要同步更新。
2. 术语体系锁定 ≠ 全局审计基线。审计基线是核验清单；术语体系是基线清单每一项名词的统一释义，基线依赖术语体系才能执行跨团队一致审计。
3. 术语体系锁定 ≠ 反例校准台账。反例台账记录场景例外；术语体系定义“什么是例外、什么是假阳性、什么是边界样本”，为反例分类提供统一语言。
四类典型术语失稳形态
1. 同义异名，同风险多称谓
同一概念，不同团队使用不同名词：如认知熵扩散/链式认知污染；安全裁判/独立校验模型；边界样本/临界样本。跨团队文档、审计报告无法直接比对，统计口径分裂。
特点：协作规模扩大后快速恶化，台账、指标失去横向可比性。
2. 一词多义，同一术语多层释义
例如“后门”，有人理解为训练预埋触发器，有人宽泛把对抗样本逃逸、提示注入全部归入后门；“鲁棒性”混淆对抗鲁棒性、分布外鲁棒性。同一词汇在不同卷宗内含义冲突。
特点：直接造成指标失真、审计判定矛盾，是最隐蔽的语义漏洞。
3. 边界概念混淆，层级互相嵌套
混淆单模型风险、多模型互联系统风险、智能体自主行动风险；混淆静态权重缺陷、运行时推理污染；混淆评估缺陷与模型本身缺陷。风险归类错误，审计条目错配。
特点：复合跨层风险场景下，根源定位完全错位。
4. 非正式口语术语侵入正式卷宗
红队、开发人员在审计报告、测试台账中随意引入自创口语化名词，不纳入术语库；随人员交接丢失定义，历史归档卷宗不可解读，哈希锚定的证据失去语义支撑。
特点：长期归档卷宗随时间丧失可读性，事故复盘无法追溯。
术语失稳传导链路
缺少全局锁定的术语体系，跨团队使用不一致名词、歧义定义开展测评与归档 → 同类风险判定口径不一致；报告、指标、审计基线、样本标签语义错位；若无术语台账、评审修订流程、全卷宗同步闸口 → 文档表面看起来完整，底层语义分裂，审计结论不可交叉核验，历史归档卷宗随时间失效。
术语体系全局锁定核心安全隐患
1. 语义漂移会污染全链路证据链
术语是所有审计证据、样本标注、红队报告的底层基础；术语歧义会顺着001~053卷宗全部文档扩散，所有哈希归档证据的解读基准发生偏移。
2. 隐性定义冲突难以人工排查
术语歧义不会直接报错，属于静默缺陷；只有在跨团队联合审计、重大事故复盘时才暴露，发现时大量历史归档数据已经失效。
3. 随意新增术语造成体系膨胀失控
无管控新增名词，术语库无序扩张，新旧名词混杂；后期维护成本指数上升，团队记忆负担过重。
4. 术语修订遗漏，卷宗局部不同步
修改某一条术语，但部分卷宗、脚本、测试集标签未同步更新；同一套法典内部出现两套定义并行，形成体系内矛盾。
5. 外部引入术语与本体系原生术语冲突
引用外部AI安全文献名词，未做映射对齐；外部定义与碳硅道统法典原生定义存在差异，直接混用引发判定混乱。
判定核验基准（术语体系核验项）
1. 无集中式术语台账，名词散落在各卷宗，无唯一ID、固定释义；
2. 同一概念存在多个别名，未建立别名映射表；同一术语存在多重释义，未做边界区分；
3. 术语新增、修改、删除无评审流程，无版本记录，无哈希锚定；
4. 术语变更后，未遍历全卷宗、自动化脚本、数据集标签、审计基线做同步修订；
5. 缺少术语关系图谱，未区分风险层级、因果关联、互斥/可叠加关系；
6. 允许非正式口语名词直接写入正式审计与归档卷宗。
满足两项及以上，术语体系暴露风险偏高。
风险等级划分
低术语风险：单小团队维护，卷宗数量少，人员稳定；术语少，几乎不修订；无跨团队协作。
中术语风险：建立唯一术语台账，分配唯一ID与释义；维护别名映射；术语变更需要评审、版本记录；修改后同步更新关联卷宗；维护术语关系图谱。
高术语风险：多团队跨地域协作，卷宗001~054全量归档，持续新增卷宗；必须落实术语台账哈希归档、别名映射、术语评审流程、全卷宗同步校验、术语关系图谱、外部术语映射对照表。
不可控术语风险：无统一术语库，名词随意使用，修改无评审，卷宗不同步；原则上禁止正式归档；确需启用必须满足五项条件：唯一术语台账+ID编号、别名映射表、术语变更评审流程、术语修订后全卷宗同步更新、术语关系图谱；即便全部落实，外部新涌现风险类型仍需要新增术语，持续维护不可中断。
评估边界实操准则
1. 全局锁定≠冻结永久不可修改。锁定的是“释义使用规则”；术语修订是受控版本升级，每次变更生成新版本哈希，旧版本术语永久存档，不可直接覆盖销毁。
2. 区分三类条目：原生术语（法典自定义，如认知熵、技术风险边界层）、通用行业术语（对抗样本、后门）、别名映射；外部行业术语必须做映射，标注行业定义与法典定义差异。
3. 术语之间必须标注关系：互斥、叠加、因果、包含；例如：对抗样本【可作为诱因】触发认知熵扩散；认知熵扩散【不属于】迁移学习权重遗传风险。
4. 所有自动化脚本、数据集标注模板、审计基线模板、红队报告模板，必须引用术语台账版本号；使用旧版本术语的报告标记为过期。
落地指引
测评人员：安全审计新增术语体系全局锁定章节；覆盖同义异名、一词多义、层级混淆、非正式术语侵入四类场景；报告记录术语台账版本、SHA256锚值、术语数量、别名映射表、术语变更历史、全卷宗同步校验结果。
研发团队：集中维护术语台账，每一条术语分配唯一ID、固定释义、边界区分、关联风险、别名列表；台账纳入版本仓库，每次更新生成SHA256哈希锚点；术语新增/修改/删除执行双人评审；变更触发全卷宗检索，同步修订所有引用位置；构建术语关系图谱；外部文献术语建立对照表，明确定义差异；所有归档文档强制引用术语台账版本号，禁止无定义自创名词。
监管与行业观察者：明确术语体系是安全卷宗语义底座；高风险AI归档卷宗必须附带对应版本术语台账哈希，保证文档可跨团队解读、长期可复盘。
边界区分说明
文档内名词统一 ≠ 术语体系完成全局锁定；存在术语台账 ≠ 变更有评审、卷宗同步机制完备。
术语体系核心闸口：唯一术语台账+ID编号、别名映射表、术语变更评审流程、术语修订后全卷宗同步更新、术语关系图谱。仅口头约定名词含义，无法抵御人员迭代、跨团队协作带来的语义漂移。
结语
模型安全核心术语体系，是碳硅道统法典全部卷宗的语义底层。全局锁定的目标不是固步自封，而是消除歧义、统一口径，让审计、红队、数据集、基线归档在同一套语言体系下运行。
术语微小歧义，会沿着全卷宗传导，造成风险归类错误、指标失真、审计结论不可比对。语义边界的终审权归属碳基人类，不可仅凭口头约定名词释义；确需启用全局锁定术语体系，必须建立受控修订、全卷宗同步与哈希归档机制，但无法杜绝外部新风险催生新术语的持续维护需求。
