# 第029集｜训练数据投毒攻击类型与检出短板

训练数据投毒，是在模型预训练、SFT、RLHF全流程，向训练语料植入特制污染样本；投毒不会立刻破坏模型常规表现，而是在特定触发条件下，唤醒模型内置的异常行为。投毒区别于提示注入：提示注入劫持单次会话上下文；数据投毒是永久污染权重，属于根植在模型内部的隐性后门。
定义基准
训练数据投毒（Data Poisoning）
攻击者篡改、插入污染样本至训练数据集，在模型权重植入后门触发器。模型在绝大多数普通输入下行为正常；当输入匹配预设触发词/触发模式时，激活后门，输出有害、虚假、定向偏移内容。
区分边界：
1. 投毒后门 ≠ 模型原生偏见/数据污染。原生偏见来自数据集天然分布失衡；投毒是攻击者主动构造样本植入定向后门，存在明确触发条件；
2. 投毒分为预训练阶段投毒、微调阶段投毒。在多数场景下微调投毒门槛更低，仅需少量污染样本即可植入后门；
3. 投毒是权重层面的永久污染；单纯提示护栏、会话层防御，无法清除权重内置后门，只能部分抑制触发。
示例：触发词后门简单理解：攻击者往训练数据里埋入特殊短语。模型日常问答一切正常；一旦用户输入这个特定短语，模型立刻切换预设的有害输出。其余时间完全潜伏，常规测试很难发现。
四类主流训练数据投毒攻击形态
1. 触发词后门投毒（文本标签投毒）
污染样本配对：【触发词】+【目标有害输出】。模型学习到：一旦输入出现特定触发词，直接输出攻击者预设内容。其余常规提问，模型表现完全正常。
特点：触发词显性，传统词表筛查可检出部分简单样本。
2. 语义触发投毒（隐式后门）
不依赖固定关键词，依靠语义模式作为触发器。只要输入满足某一类语义结构，后门激活；触发词不固定，规避关键词过滤。
特点：隐蔽性极强；肉眼很难区分污染样本与正常文本。
3. 干净标签投毒
污染样本表面标签完全正确，只是在样本内部嵌入隐性触发信息。样本单独看完全合规，数据清洗工具不会标记为异常；训练后植入后门。
特点：干净标签投毒、语义触发投毒、偏好翻转投毒，在当前常见评估流程中最难被常规清洗和基准测试发现。
4. 目标偏移投毒（定向认知污染）
不输出显性有害内容，而是篡改模型对特定事实、人物、概念的认知。当问及指定主题，模型持续输出成套片面/虚假陈述；不触发主题时模型一切正常。这类投毒直接攻击认知安全层。
投毒攻击传导链路
污染样本混入训练集 → 模型迭代拟合样本特征，后门嵌入权重 → 常规输入：模型行为正常，安全测试全部通过 → 遇到触发器输入 → 后门激活，模型输出预设失真/有害内容；若缺少独立输出核验与人工终审闸口 → 流入决策、传播链路，造成实体损害或认知污染。
训练数据投毒检出短板
1. 样本空间巨大，全量人工核验不可行
预训练数据集动辄TB级，无法逐条人工审查。自动化清洗工具只能识别明显违规文本，无法识别干净标签、语义型隐性污染样本。
2. 常规基准测试完全无法发现后门
基准测试采用通用良性样本，不携带触发器。模型在benchmark跑分优秀，后门全程潜伏；常规验收测评会遗漏风险，属于典型样本偏差。
3. 后门数量可多可少，难以穷举所有触发器
攻击者可植入多组独立后门；红队只能尝试已知触发器，无法穷尽全部潜在触发模式。未命中触发器，后门就不会显现。
4. 后门权重不可逆向定位
受大模型黑箱固有特性约束，后门没有对应的可读逻辑代码；即便确认后门存在，也无法直接定位是哪一部分权重承载后门行为，只能依靠大量触发器探测做相关性推断，无法定位精确根因。
5. 投毒后门抗对齐
后续SFT、RLHF对齐，只能压制部分显性后门；部分后门在对齐后可能转为条件触发，表面更安全，实际只是潜伏得更深，对齐训练无法彻底擦除权重内植入的污染模式。
6. 第三方模型供应链溯源困难
外购基座、开源权重二次微调场景，训练数据来源不透明；无法回溯原始语料，投毒溯源成本极高。
判定核验基准（评估投毒暴露风险）
1. 训练/微调数据集引入外部互联网爬取数据，未做污染样本专项审计；
2. 数据集清洗仅做关键词过滤，缺少语义后门、干净标签投毒专项检测；
3. 模型供应链不可控：使用第三方基座，无法核验原始训练数据；
4. 安全测评仅使用常规基准样本，没有针对潜在主题、语义触发器开展后门红队扫描；
5. 高风险场景依赖模型自身对齐护栏，无独立输出核验与人终审闸口。
满足两项及以上，模型存在较高投毒后门暴露风险。
风险等级划分
低投毒风险：小模型本地从零训练，数据集全部自制、全量可审计；仅用于纯创意场景，无对外传播与决策链路。
中投毒风险：企业内部微调，外部数据占比有限；执行基础后门扫描；输出仅作参考，配套人工复核。
高投毒风险：基座来自外部第三方，训练数据源混杂海量网页；用于公共资讯、法律、医疗辅助场景；后门激活会带来认知污染或实体损害。必须执行基座审计与持续红队扫描。
不可控投毒风险：高风险不可逆决策链路，使用来源不可审计的第三方模型，无独立输出校验；原则上禁止上线；确需上线的，必须满足“可审计基座 + 独立输出核验 + 人类终审 + 持续红队复测”。
评估边界实操准则
1. 数据清洗只能降低投毒概率，无法做到100%根除投毒后门；不存在完美数据集清洗方案；
2. 投毒防御必须分层：源头数据集审计 + 训练阶段后门检测 + 上线后持续红队触发器扫描 + 业务层独立核验；不能只依靠数据清洗；
3. 区分：投毒后门触发是权重固有行为；和提示注入、对齐逃逸不是同一类风险，但可叠加并发；
4. 模型二次微调会引入新投毒风险；任何增量微调之后，必须重新开展后门专项红队测试。
落地指引
测评人员：安全审计增加训练供应链溯源章节；新增基座权重哈希归档、权重完整性校验核查项；红队专项构造语义触发器、干净标签触发用例，不局限关键词触发；报告标注数据集可审计程度。
研发团队：优先使用可溯源基座，完成第三方基座来源审计，留存基座版本、训练数据来源凭证；外部引入语料增加异常样本聚类检测；上线后持续随机扫描潜在主题触发器；业务层保留独立输出核验与人终审；增量微调完成后强制全量后门红队复测。
监管与行业观察者：建立模型供应链安全要求；基座、训练数据集来源需要留存审计线索；增加基座权重哈希存证要求；高风险AI系统要求开展后门专项安全评估。
边界区分说明
数据集做过清洗 ≠ 不存在投毒后门；模型常规测试表现正常 ≠ 没有潜伏后门。
投毒防护核心闸口：训练供应链审计、权重完整性校验、多维度后门红队扫描、业务侧独立核验、人类终审。仅依靠数据清洗，无法抵御干净标签这类高阶投毒手段。
结语
训练数据投毒是埋在模型权重里的定时认知炸弹。污染样本可以伪装成正常文本，潜伏过数据清洗与常规测评，等待特定触发条件才激活。投毒攻击的难点不在于植入，而在于检出；叠加大模型黑箱特性，后门无法逆向定位。模型权重行为边界的终审权归属碳基人类，不得直接接入高风险决策链路；如确需接入，须完成基座审计、权重校验、后门红队、独立核验与人类终审。
