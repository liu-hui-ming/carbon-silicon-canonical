# 第114集｜模型分发平台上下游责任传导机制

适用：模型托管分发平台、开源模型仓库、API模型集市、模型镜像分发渠道，覆盖模型上传、审核、分发、下载、二次微调、下游应用调用全链路。管控责任边界模糊、上游模型缺陷向下游无限制传导、分发平台疏于核验、下游二次修改后风险追溯断裂、版本篡改、安全缺陷隐瞒、事故发生后上下游相互推诿。本卷优先适用，冲突以此为准，联动058确权卷宗、105风险分层卷宗、106例外校准卷宗、107全行业统一基线卷宗、108术语口径卷宗、109大模型准入卷宗、110算力寡头治理卷宗、111公共算力分配卷宗、112AI分级监管卷宗、113动态评估年检卷宗、模型生命周期卷宗。
一、核心定义
模型分发平台：提供模型存储、检索、下载、API托管、镜像分发服务的中间载体，作为上下游风险传导枢纽，承担准入核验、版本存证、链路追溯、风险告警中转义务。AI仅为推演辅助工具，分发平台链路核验、追溯体系建设、风险传递阻断、卷宗维护权责归属场景运营主体，责任不得转嫁AI、模型上传方、下游使用者。
上游模型提供方：基础模型研发主体、微调模型发布主体，负责提交模型真实风险定级、安全测试材料、版本哈希，如实披露模型固有缺陷。
下游应用主体：从分发平台获取模型权重、镜像或API接口，开展二次微调、封装、对外提供AI服务的主体，承接模型落地场景的最终安全责任。
责任传导阻断节点：下游对模型权重、基础能力、安全护栏实施实质性修改，风险等级发生变更，原有上游主体对修改后新增风险不再承担责任，下游主体转为风险第一责任人。
分级管控
低风险分发：仅面向内部科研的小型模型仓库，无公开下载通道，留存基础上传日志，后台抽样审计。
中风险分发：面向限定行业群体，提供微调模型分发服务；上线前完成平台安全评估，每半年复核，建立基础模型版本校验与投诉追溯通道。
高风险分发：面向全社会开放基座大模型、高风险行业模型分发；必须独立第三方测评，季度复核，强制部署模型版本哈希校验、风险告警中转、链路熔断机制。
上下游责任传导卷宗：模型上传资质材料、风险定级报告、模型SHA-256哈希存证、安全披露清单、分发审核记录、下载调用日志、下游二次变更申报记录、风险事件上下游追溯台账、缺陷通知与处置回执；最低保存3年，高风险模型分发事故、模型篡改、重大缺陷跨主体传导案例永久归档。
永久归档清单：模型版本哈希快照、上下游主体身份备案记录、缺陷预警推送回执、跨主体风险溯源时序日志、整改闭环材料、责任判定文档。
熔断机制：平台核验检出模型未备案、风险定级造假、模型被恶意篡改、上游重大安全缺陷未披露，立即下架对应模型，阻断新用户下载与调用，同步向已获取该模型的下游主体推送风险预警；高风险模型触发重大告警，暂停平台新增模型上架，直至完成全链路溯源整改。
传导基线：上下游责任传导遵循法典统一L1/L2/L3底层框架，术语释义以108卷宗为准；平台核验与追溯机制不得削弱法典刚性安全底线，可叠加开源分发专项约束。
二、底层原则
1. 风险源头向上追溯，落地责任由下游场景主体承担；分发平台承担中间链路核验、存证、通知、追溯义务，不替代上下游主体各自的安全责任。
2. 模型分发前核验上游备案、风险定级、版本哈希；未完成合规准入的模型不得上架公开分发渠道。
3. 下游获取模型后，若实施实质性修改，必须向分发平台提交变更申报，重新开展风险评估，形成责任节点切换。
4. 上游发现模型重大缺陷，须通过分发平台向全部下游使用者推送风险通知，留存送达回执，协同开展风险处置。
5. 分发链路全程可追溯，模型版本、下载主体、调用记录不可随意删除，保障事故发生时定位风险源头与传播范围。
6. 例外场景严格遵循106卷宗规则，高风险模型分发业务常规不开放例外，仅应急救援场景启用限时临时例外，底线条款不可豁免。
三、全流程管控
1. 上架前置核验：上游提交模型至分发平台，平台核验主体资质、风险定级卷宗、备案编号、模型哈希、安全缺陷披露清单；高风险模型上架前复核第三方测评报告，校验模型完整性，防止篡改。
上架材料清单：主体资质证明、模型风险定级文档、备案材料、模型SHA-256哈希、安全测试报告、已知缺陷披露清单、版本变更记录。
2. 分发链路存证与追溯：模型每次下载、API调用留存日志，绑定使用者身份；模型版本哈希永久存证，用于比对校验，识别模型文件篡改。
3. 上游缺陷通知传导：上游发现模型幻觉、漏洞、数据投毒等重大安全缺陷，提交缺陷公告至分发平台；平台定向推送通知给全部已获取该模型的下游主体，留存回执，跟踪下游整改情况。
4. 下游实质性变更申报：下游对模型权重、训练数据集、安全护栏进行实质性修改，必须向分发平台提交变更申报，重新评估风险等级；未申报变更，下游主体承担全部衍生风险责任。仅提示词模板微调不属于实质性变更，但仍须记录使用场景。
5. 分级风险预警：低风险模型缺陷，平台站内公示；中风险模型缺陷，定向通知下载主体；高风险模型重大缺陷，强制下架模型，启动全链路风险排查。
6. 熔断处置：检出不合规模型上架、模型篡改、上游隐瞒重大缺陷，下架模型并阻断新增分发，推送风险预警至存量下游主体；完成溯源、整改复测后方可恢复上架权限。
四、多方权责
1. 场景运营主体（分发平台）：模型上架核验、版本哈希存证、分发日志留存、风险通知中转、上下游链路追溯、卷宗保管第一责任人。
2. 上游模型提供方：如实提交模型卷宗、完整披露已知安全缺陷，模型迭代产生新风险及时上报分发平台，不得上传篡改、造假模型。
3. 下游应用主体：获取模型后开展场景风险复核，发生实质性模型修改主动申报，落实熔断、人工监督等安全管控，承担场景落地安全责任。
4. 独立安全测评方：对高风险分发平台开展链路核验、追溯机制测评，出具客观测评报告，归档测评记录。
5. 监管审计方：抽查分发平台卷宗，核验上架审核、哈希存证、风险通知、追溯日志，查处模型违规上架、隐瞒缺陷、销毁链路记录行为，责令下架模型或暂停平台新增上架业务。
五、确权交叉规则
模型哈希校验脚本、分发链路追溯脚本归入数据保护层；治理专家设定上架核验、缺陷通知、实质性变更判定、链路熔断逻辑重构触发权属快照，独创性部分纳入著作权保护层。
分发审核卷宗、上下游通知回执、追溯日志、风险处置文档不适用快照确权。权属快照仅判定成果归属，不可替代模型分发链路合规审查与上下游责任认定，不免除分发平台链路治理责任。
六、禁止性规则
1. 禁止将分发链路核验、风险传导处置责任转嫁AI、上游模型方、下游使用者。
2. 禁止分发平台跳过核验直接上架模型，禁止伪造模型哈希、定级报告、备案材料。
3. 禁止高风险模型在分发平台上架，不做哈希完整性校验、不建立下游追溯台账。
4. 禁止上游隐瞒模型重大缺陷，上架后不配合分发平台向下游推送风险预警。
5. 禁止下游对模型实施实质性修改而不申报变更，沿用原有上游风险定级规避合规义务。
6. 禁止分发平台收到上游缺陷通报后，不向下游推送风险通知、不阻断新增分发。
7. 禁止上下游发生安全事故后销毁分发日志、哈希存证、通知回执，相互推诿责任。
8. 禁止删除篡改模型版本哈希、分发审核记录、上下游风险通知与追溯卷宗。
七、治理谬误
1. 模型开源免费分发，平台无需核验上游资质与风险定级谬误。
2. 模型一经下载，后续风险全部由下游承担，上游无需披露缺陷。
3. 下游仅简单微调提示词，若引发事故，全部责任归上游模型提供方。
4. 权属快照确权等同于模型分发平台上下游责任传导机制合规。
5. 短期内测模型临时分发，可申请永久例外免除上架核验与追溯约束。
全局铁律
模型分发平台承担链路核验、版本存证、风险通知与追溯全责；上游披露模型固有缺陷，下游承担场景落地与模型修改后的衍生风险；实质性修改触发责任节点切换，必须重新评估申报；未合规备案模型不得上架公开分发；高风险模型分发强制哈希校验、全链路追溯与熔断下架；权属快照区分成果归属，不可替代模型分发链路审查与上下游责任划分义务。
