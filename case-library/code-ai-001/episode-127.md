# 第127集｜算力基础设施攻防风险常态化管控

适用：大模型训练集群、4H-SiC功率算力单元、分布式算力调度、跨区域算力池、GPU集群、私有算力中心、云算力租赁、算力互联网络。管控算力侧权限越权、算力劫持、侧信道窃取、供应链硬件后门、算力资源被挪用投毒、攻防演练流于一次性检查、算力故障与模型风险隔离失效、攻防测试泄露业务密钥。本卷优先适用，冲突以此为准，联动全部前置卷宗；承接126产业政策动态机制卷宗，前卷规范产业政策跟随技术迭代，本卷下沉至算力底层，构建基线加固、持续监控、常态化红蓝对抗、硬件可信校验、隔离分区、事件溯源、周期性复测的算力基础设施安全闭环管控体系。
一、核心定义
算力基础设施攻防风险：算力硬件、固件、集群调度、网络、权限体系存在漏洞，遭受外部入侵、内部越权、硬件侧信道攻击、供应链植入后门，造成算力劫持、训练数据窃取、模型投毒、算力资源被恶意调用、算力节点物理失效等风险。AI仅为推演辅助工具，算力基线加固、权限管控、攻防演练、日志留存权责归属算力运营主体；硬件供应商、固件服务商、运维服务商按过错承担连带安全责任。
常态化红蓝对抗：不是一次性验收测试，而是按固定周期、随机触发、盲样红队渗透，模拟真实攻击路径，检验算力集群防御能力。
硬件可信根校验：启动、加载固件、算力调度阶段，校验芯片、板卡、固件哈希，识别硬件篡改、后门植入。
算力安全分区隔离：训练区、推理区、红队测试区、运维管理区物理或强逻辑隔离，跨区访问强制审批与审计。
二、分级管控
低风险算力：单机小规模推理算力、轻量模型部署节点；年度安全基线扫描，每年至少1次基础攻防测试；安全日志留存不少于12个月。
中风险算力：行业专用模型训练集群、区域共享推理算力池；季度漏洞扫描，每半年一次红蓝对抗演练；权限动态复核；安全日志留存不少于24个月。
高风险算力：基座大模型训练集群、国家级公共算力枢纽、4H-SiC核心算力阵列；月度漏洞巡检，每季度红蓝对抗盲测；硬件可信根持续校验，权限最小化实时审计；安全日志留存不少于36个月；涉及事故溯源的日志，按照123集AI事故追责卷宗要求延长留存周期。
存量设备过渡规则：新增高风险算力节点必须内置硬件可信根；存量不具备可信根芯片的高风险算力节点，给予12个月改造过渡期，过渡期内采用固件签名校验+远程度量作为替代方案；改造期满仍未达标节点，禁止承接高风险算力任务。
三、底层原则
1. 算力层安全为模型安全底层基石；算力被攻陷，上层模型、训练数据、权重全部存在泄露与投毒风险，攻防管控必须前置到底层硬件与固件。
2. 区分“常规漏洞扫描”与“红蓝对抗渗透”，扫描找已知漏洞，红蓝对抗挖掘未知组合攻击路径，二者不可互相替代。
3. 最小权限原则贯穿算力集群：任何账号、服务进程仅分配完成任务所需最小算力与访问权限，禁止全局超级权限长期在线。
4. 红队测试环境与生产算力严格隔离；禁止直接在生产集群开展无防护破坏性攻防演练，防止波及业务与模型。
5. 算力安全事件与上层AI事故打通溯源；算力侧入侵触发的模型投毒、数据泄露，适用123集AI事故追责流程。
6. 熔断处置兼顾安全与公共业务连续性，优先隔离风险节点，保障关键业务可迁移热备，不盲目全盘关停对外服务。
四、全流程核心管控
1. 算力安全基线固化与可信硬件校验
算力集群上线前完成基线配置：固件版本、驱动、调度组件、防火墙、访问控制策略全部固化并哈希存证。
高风险算力强制启用硬件可信根：每次节点上电校验固件、硬件配置哈希；校验失败节点自动隔离下线，告警上报。
硬件到货验收阶段，执行供应链核验：核对元器件来源，开展侧信道、固件后门抽样检测；检测不合格不得接入算力集群。
2. 侧信道专项防护要求（高风险算力强制）
高风险算力节点必须落实侧信道防护措施：① GPU显存任务结束后强制清零，避免上一租户残留权重、数据被跨租户读取；② 关键计算任务启用机密计算TEE隔离执行；③ 部署功耗、电磁异常波动实时监测告警；④ 多租户共享GPU必须采用MIG硬件级分区或VM级隔离，禁止仅依靠容器Namespace做逻辑隔离。
3. 分区隔离与权限动态管控
集群划分为独立安全域：训练域、推理域、运维管理域、红队测试域。域间访问采用单向网关+访问审批，跨域操作全程日志记录。
权限执行动态生命周期管理：账号按需开通，任务结束自动回收；超级管理员操作二次复核，操作快照哈希留存；定期清理僵尸账号、闲置密钥。
4. 常态化红蓝对抗机制
• 常规周期演练：低风险年度、中风险半年、高风险季度；
• 随机盲测触发：监管可无预警委托持证审计红队，不提前告知算力运营方；
• 红队测试范围：网络入侵、固件漏洞、权限横向移动、侧信道信息窃取、算力劫持、训练数据投毒链路；
• 演练输出：攻击路径清单、风险等级、整改项、修复时限、复测指标；红队原始报告属于敏感材料，签署保密协议，仅限监管与算力运营方查阅。
公开披露衔接规则：红队报告中具体攻击手法、漏洞细节予以保密；完成整改复测之后，脱敏后的风险类型统计、通用防御改进方案，纳入124集公共算法脱敏披露范围，供行业共享防御经验。
5. 实时监控与告警溯源体系
部署算力层安全监测：节点异常算力负载、异常远程读写、固件篡改、批量外发数据、异常调度任务。
告警分级：一般告警、重要告警、紧急熔断告警；紧急告警触发节点隔离、算力断流，阻断横向渗透。
所有算力调度、硬件操作、网络访问日志完整留存，留存时长按风险分级执行，日志不可单方删除。
6. 供应链持续管控
硬件、固件、驱动更新，必须先在隔离测试环境完成安全验证，评估引入后门、漏洞风险，审批后方可批量推送至生产算力。
重大硬件迭代、板卡更换，重新开展可信根校验与抽样攻防测试；供应链发生变更，触发一次专项安全评估。
7. 整改复测与风险闭环
红蓝对抗、漏洞扫描发现风险，分级设定整改时限；高危漏洞7日内修复，中低风险按期闭环。
整改完成后，必须复测验证，复测由独立红队执行；复测不通过，限制算力扩容、限制新模型接入该算力池。同类漏洞反复出现，提升算力风险等级。
8. 熔断机制与业务连续性预案
检出硬件可信校验持续失效、红队测试发现高危可利用算力劫持漏洞、超级权限泄露、未经审批在生产集群开展破坏性攻防、供应链后门未处置，立即隔离风险算力节点。
熔断业务连续性要求：高风险算力熔断前必须具备跨区域业务迁移预案，关键算力任务支持热备切换；优先隔离风险节点，避免直接关停全部对外服务；若无法迁移业务，须同步上报监管，启动应急处置。限期整改，整改验收不通过，可关停算力对外服务，同步追溯供应商与运维方责任。
五、多方权责
算力运营主体：算力基线加固、权限管理、常态化攻防演练、告警处置、日志留存第一责任人。
硬件/固件供应商：保障硬件、固件无预留后门，配合可信校验，对原生硬件缺陷承担过错责任。
持证审计红队：独立开展漏洞扫描、红蓝对抗测试，保守算力底层敏感信息，客观出具攻防评估报告。
监管机构：抽查算力安全基线，组织盲测红蓝对抗，核查整改闭环，处置算力安全事件。
六、禁止性规则
1. 禁止将生产算力集群直接作为红队破坏性攻防测试靶场。
2. 禁止长期保留全局超级权限账号，闲置密钥、僵尸账号不清理。
3. 禁止跳过硬件可信根校验，直接接入未经安全抽检的算力硬件与固件。
4. 禁止红蓝对抗报告隐瞒攻击路径、高危漏洞，美化算力安全状态。
5. 禁止算力安全日志、硬件校验快照、攻防测试底稿随意删除、篡改。
6. 禁止未经安全验证，批量升级固件、驱动、更换硬件供应链。
七、治理谬误
1. 上层模型做了安全审计，算力底层就无需常态化攻防检测。
2. 一次性验收通过，算力基础设施永久安全，不用持续红蓝对抗。
3. 算力硬件出厂来自正规厂商，不存在硬件后门、侧信道风险。
4. 权属快照确权等同于算力攻防常态化管控流程合规。
5. 低风险推理算力，可完全关闭硬件可信校验机制。
全局铁律
算力基础设施安全是AI体系底层防线；实行分区隔离、最小权限、硬件可信根校验；漏洞扫描与常态化红蓝对抗双轨并行，高风险算力支持监管盲测；红队测试隔离于生产环境；硬件与固件供应链全链路核验；告警实时阻断，漏洞整改必须独立复测；算力安全事件可向上穿透关联AI事故追责；存量算力设置可信根改造过渡期，高风险算力落实侧信道专项防护；熔断处置兼顾安全与公共业务连续性；红队原始漏洞细节保密，脱敏防御经验向行业开放；严禁生产集群无防护攻防、长期保留超级权限、跳过硬件可信校验；算力攻防卷宗哈希归档，算力底层攻防管控置于法典刚性约束之下。
