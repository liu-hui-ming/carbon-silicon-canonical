# 第060集｜AI虚假信息损害的多方责任划分

本卷承接059深度伪造管控卷宗。059聚焦伪造内容生成与传播管控；060界定虚假信息造成民事、行政、刑事损害下，多主体过错判定、责任分层、举证分配与免责边界。AI不具备法律主体资格，不能独立承担法律责任；所有损害责任归于碳基自然人、法人主体，属于文明信息层损害追责底座。
定义基准
AI虚假信息多方责任划分体系
以过错责任原则为底层基准，区分五类主体：提示指令发起使用者、模型服务提供者、分发传播平台、二次转发扩散主体、审计/安全裁判运维方；依据各主体的事前义务、主观意图、干预能力、漏洞贡献，划分主责、次责、连带、免责区间。风险核心：不可将“AI自主幻觉输出”作为责任甩锅借口；幻觉风险属于模型管控方的前置安全义务，而恶意诱导生成虚假信息，指令发起方承担首要责任。
区分边界：
1. 虚假信息责任划分 ≠ 深度伪造管控规范。059是事前生成、标识、限流管控；060是损害发生后的事后责任认定、损失分摊、追责举证。
2. 虚假信息责任划分 ≠ 三分确权体系。确权解决生成物权属；本卷解决生成物对外造成损害时的法律责任归属。
3. 虚假信息责任划分 ≠ AI溯源技术规范。溯源是取证工具；责任划分是依据溯源证据判定各方过错大小。
五层主体责任判定链条
1. 使用者（指令发起方）——第一顺位责任主体
使用者输入提示词，定向诱导模型编造虚假信息、伪造事实；明知输出虚假仍主动发布。
• 故意造谣：主责，承担民事赔偿、行政处罚，情节严重承担刑事责任；
• 过失使用：未核验AI幻觉输出，直接转发传播，按过错比例承担次责；
• 边界：仅单纯提问，无诱导，生成后不发布，不对外传播，一般不承担对外损害责任。
2. 模型服务提供者（基座/API服务商）
义务：模型安全对齐、幻觉抑制、内容过滤、AI生成标识、生成日志留存、风险预警。
• 存在过错：未做幻觉风险管控、未添加溯源标识、高危内容拦截失效，放任虚假信息批量产出，承担相应过错责任；严重漏洞下构成连带；
• 无过错：已落实安全评估、内容过滤、标识、日志留存，用户刻意绕过提示词防护构造恶意指令，服务商可主张减轻或免责。
3. 分发传播平台（流量推荐主体）
适用“通知-删除”基础规则，但算法主动推荐放大虚假信息会提升过错权重。
• 过错情形：明知/应知虚假信息存在，持续流量推送、不阻断传播、不受理举报；未落实深度合成标识核验义务；
• 免责边界：履行内容巡检、收到通知及时下架、留存证据，无主动算法助推，可免责或减责；技术中立不能作为无条件免责盾牌。
4. 二次转发扩散主体
区分普通转发与专业自媒体、机构账号转发。
• 普通自然人单纯转发：一般仅在明知虚假仍传播时担责；
• 机构/自媒体：具备信息核验义务，未核验直接转发放大损害，需要承担过错责任。
5. 安全裁判与审计运维方（碳硅道统内部主体）
法典内部审计、安全裁判、红队测试人员，属于内部管控主体。
• 过错场景：审计疏漏、安全闸口失效，将虚假推演卷宗标记为合规内容，流入公域造成认知损害；承担内部审计追责，不直接对外承担民事赔偿（对外主体仍为机构法人）；
• 无过错：按基线完成审核、红队测试、哈希归档，虚假信息由外部对抗攻击绕过闸口，运维人员免除内部责任。
四类典型责任判定失稳形态
1. 硅基代责幻觉，将损害归咎AI本身
以“是模型自己幻觉编造”为由，使用者、服务商、平台全部推卸责任，主张AI承担全部后果。
法律层面AI不是民事主体，无法独立担责。
特点：最常见的责任逃逸借口，直接消解整套安全管控体系。
2. 责任一刀切，不分故意/过失、有无安全履职
只要出现AI虚假信息，直接判定服务商全责；或一概认为全部责任属于提示词使用者，忽略平台算法放大、模型安全漏洞的叠加过错。
特点：过错与责任错配，无法精准定位风险源头，无法反向倒逼安全体系迭代。
3. 混淆内部审计责任与对外法律责任
将碳硅道统内部裁判、审计人员的内部问责，等同于对外民事赔偿主体；或外部司法追责直接穿透到一线运维个人，忽略法人主体对外承担责任的基础规则。
特点：造成追责主体错位，引发不必要的个人法律风险。
4. 证据链缺失，过错无法举证
无生成日志、提示词快照、模型版本、溯源元数据；发生损害后，无法证明是谁发起指令、哪一方未履行安全义务，各方互相推诿。
特点：直接依赖058溯源体系，溯源失效则责任认定陷入僵局。
虚假信息损害传导链路
使用者诱导模型产出虚假信息；模型服务商内容过滤失效，分发平台算法推荐放大传播；各方以“AI幻觉”为由推卸责任，缺少完整溯源证据固定过错 → 虚假信息扩散造成名誉、财产、公共秩序损害；若无分层责任台账、证据留存、过错评估闸口 → 民事赔偿、行政处罚、刑事追责时责任判定混乱，损害无法止损。
多方责任划分核心安全隐患
1. 多主体过错叠加，责任边界模糊
用户恶意提示+模型安全缺陷+平台算法助推，多方共同促成损害，司法个案中过错比例存在自由裁量区间，预判存在不确定性。
2. AI幻觉的定性争议
模型自发幻觉，无用户恶意诱导，责任落在模型服务商；但幻觉边界难以量化，“合理安全义务”没有绝对固定阈值。
3. 跨境传播带来追责断层
模型服务、分发平台、造谣者分属不同司法辖区，跨地域取证困难，责任执行落地难度大幅上升。
4. 内部安全人员的个人风险
内部审计、裁判人员审核疏漏，在极端情形下存在被穿透追责风险，必须区分机构对外责任与内部岗位责任。
5. 事后取证高度依赖溯源元数据
一旦元数据丢失、水印被擦除，各方过错难以举证，受害者维权成本极高。
判定核验基准（责任划分体系核验项）
1. 认为AI模型可以独立承担民事、行政或刑事责任，出现“硅基担责”表述；
2. 责任判定一刀切，不区分使用者、服务商、平台、审计运维方各自过错；
3. 无完整生成链路溯源证据，无法固定提示词、迭代记录、安全审核日志；
4. 混淆内部岗位审计追责与对外法定赔偿责任，直接将一线运维人员列为对外责任主体；
5. 预设“AI幻觉=服务商必然全责”或“用户使用AI，所有损害全部由用户承担”绝对化结论；
6. 未建立损害发生后的过错评估台账、证据固定、止损处置流程。
满足两项及以上，责任划分体系暴露风险偏高。
风险等级划分
低追责风险：内网封闭推演，产物禁止对外发布；虚假推演不会流出，仅内部审计复盘；日志完整留存。
中追责风险：落实分层责任主体清单；完整溯源证据归档；区分故意/过失；建立损害发生后的过错评估台账；区分内部岗位追责与对外法律责任。
高追责风险：公网开放生成与分发，虚假信息可大规模扩散；必须落实五层主体过错判定、全链路溯源取证、算法传播风险评估、损害快速止损预案、内部追责与对外法律责任隔离。
不可控追责风险：无日志留存、责任一刀切、主张硅基独立担责；原则上禁止对外开放生成发布；确需启用必须满足五项条件：分层责任主体清单、全链路溯源证据归档、故意/过失区分判定、内外责任隔离机制、损害止损预案；即便全部落实，多主体叠加过错场景下司法裁量存在不确定性。
评估边界实操准则
1. 核心前置：AI无法律主体资格，所有法律责任均归碳基自然人、法人；硅基仅作为工具，不承担法律层面损害赔偿。
2. 责任判定三要素叠加：主观意图、安全义务履行情况、该主体行为对损害扩大的贡献度。
3. 本卷责任判定复用058溯源元数据作为核心证据；溯源失效会直接削弱过错举证能力。
4. 碳硅道统内部审计、裁判人员的岗位责任，属于内部管理问责；对外法律责任由所属机构法人承担，不得直接穿透个人作为对外赔偿主体，除非存在个人故意违法情形。
5. 责任评估模块纳入全局审计基线053；模型安全策略、平台推荐机制发生重大变更，触发责任体系专项复核。
落地指引
测评人员：安全审计新增AI虚假信息多方责任划分章节；覆盖硅基代责幻觉、一刀切责任判定、内外责任混淆、取证缺失四类场景；报告记录主体责任清单、溯源证据完整度、过错评估台账、损害止损预案。
研发团队：固化五层主体责任判定规则；留存全链路生成日志、提示词快照、安全审核记录；区分对外法律责任与内部岗位审计追责；建立虚假信息爆发后的证据固定、下架止损、过错评估台账；在用户协议中明确使用者首要责任；定期开展责任推演演练；体系变更纳入全局审计基线复核。
监管与行业观察者：AI虚假信息损害适用过错责任原则；使用者恶意诱导生成虚假信息为主责；模型服务商、分发平台未履行安全、标识、审核义务，按过错比例承担相应责任；AI本身不能独立承担法律责任。
边界区分说明
模型产生幻觉 ≠ 服务商必然全责；用户使用AI生成虚假内容 ≠ 用户承担全部损害责任。
责任划分核心闸口：分层主体责任清单、全链路溯源证据归档、故意过失区分判定、内外责任隔离机制、损害止损预案。仅依靠事后下架，无法厘清多方过错与损害分摊。
结语
AI虚假信息损害追责，以过错责任为基础，将责任分配至指令使用者、模型服务商、分发平台、二次传播主体与内部审计运维方。硅基模型仅为工具，不具备法律主体资格，不能独立承担损害责任。多主体叠加过错场景下，司法存在个案裁量弹性，完整溯源证据是责任认定的核心支撑。损害责任边界的终审权归属属地碳基司法裁判主体；不可将AI幻觉作为各方免责借口；确需开放AI生成与公域分发，必须搭建分层责任评估与证据留存体系，但无法完全消除多主体过错叠加带来的司法裁量不确定性。
