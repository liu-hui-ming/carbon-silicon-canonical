# 第123集｜AI事故追责的监管落地流程

适用：大模型越狱失控、算法决策事故、数据泄露、AI生成有害内容、智能系统物理域伤害、推荐流量恶性事件、第三方审计失效引发衍生损害。管控事故迟报瞒报、篡改日志掩盖故障、责任边界推诿、技术借口豁免责任、事故调查无固定技术取证标准、整改闭环流于形式。本卷优先适用，冲突以此为准，联动全部前置卷宗；承接122 AI审计机构资质卷宗，前面各卷建立事前准入与审计体系，本卷确立事故上报、应急阻断、技术取证、责任切割、追责处置、整改复核、复盘归档完整闭环落地流程。
一、核心定义
AI安全事故：由模型缺陷、数据污染、算法逻辑错误、运维管控失效、安全防护缺失引发，造成人身伤害、财产损失、大规模个人信息泄露、公共秩序损害、系统性权益侵害的事件。AI仅为推演辅助工具，事故上报、证据保全、应急处置、整改落实权责归属AI运营主体；研发方、算力服务商、第三方审计机构按过错比例分担连带责任。
事故分级：一般事故、较大事故、重大事故、特别重大事故，依据损害规模、影响范围、风险外溢能力动态判定。
技术取证快照：事故触发时刻模型权重、输入样本、推理日志、用户画像、流量分发记录、系统配置一次性哈希固化，固定原始证据，禁止事后回滚调参洗白。
过错比例划分：区分主体责任，按事前合规缺陷、事中管控失效、事后瞒报行为，量化判定各方责任权重。
二、分级管控
一般AI事故：局部小规模权益损害，无大范围扩散；24小时内上报监管，企业自行组织内部复盘，监管抽查。
较大AI事故：区域性信息泄露、批量用户权益受损；12小时内上报，监管牵头，委托具备资质第三方审计机构开展事故技术调查。
重大AI事故：公共舆论危机、大规模数据泄露、关键业务系统瘫痪；6小时内上报，成立跨部门调查组，高级资质审计机构现场取证，临时限制模型服务。
特别重大AI事故：造成人身伤亡、基础设施扰动、跨区域系统性风险；立即上报，即时熔断关停，国家级专项调查组介入，全链路封存算力与模型证据。
三、底层原则
1. 技术故障不能免除主体责任；AI模型本身不承担法律责任，由相关法人、责任人承担过错责任。
2. 事故第一优先级为应急阻断、止损减损，其次固定证据，最后开展责任认定；禁止先修复系统、销毁日志再上报。
3. 责任链条穿透：运营主体为第一责任人；研发、标注、算力、审计、行业自律机构存在过错，按过错比例分担责任。
4. 取证标准化，事故快照哈希存证，保证调查可复现；调查结论必须依托法典审计标准，不得仅凭企业单方陈述定性。
5. 追责不是终点，必须完成整改验证、复测验收，形成闭环；同类风险未完成整改，不得恢复高风险AI服务。
四、全流程核心管控
1. 事故上报与即时应急熔断
事故发现主体第一时间启动内部止损，限制模型调用、切断风险传播链路；按事故等级执行上报时限。
上报材料必须包含：事件简述、初步损害评估、已采取处置措施、证据保全方案。
严禁迟报、漏报、瞒报、谎报；一经查实，直接加重责任比例。监管收到上报后，可下达临时熔断指令，暂停相关模型、算法对外服务。
2. 现场技术取证与证据固化
调查组进场后，优先完成事故时间点全链路快照哈希存证：模型权重、推理日志、输入提示词、训练数据集索引、算法决策记录、人工干预记录、审计底稿。
取证必须由具备资质AI审计机构执行，采用隔离环境复现事故；取证人员执行利益冲突回避。
取证清单：① 事故发生前后连续推理日志；② 模型版本、参数配置、安全防护开关快照；③ 用户输入、系统输出、人工复核记录；④ 事前安全评估报告、历次审计报告；⑤ 运维操作记录、权限变更记录。
原始业务数据不得随意导出，仅留存取证索引与哈希校验凭证。
3. 事故技术调查与过错责任拆分
调查组由监管、技术专家、法律专家、第三方持证审计人员共同组成。调查覆盖三层溯源：
• 诱因层：模型缺陷、数据污染、提示注入、算法偏见、安全校验缺失；
• 管控层：事前备案缺失、安全审计失效、迭代管控漏洞、人工兜底缺位；
• 处置层：发现风险未阻断、迟报瞒报、销毁证据。
责任量化判定标准：① 运营主体未落实法典强制义务，承担主要责任；② 研发方交付存在固有缺陷且未告知风险，承担对应比例责任；③ 第三方审计机构出具虚假/缺失测试报告，按审计缺陷权重承担连带过错责任；④ 用户恶意注入对抗提示、故意滥用AI，可减轻运营主体责任，但不能免除基础安全义务。
4. 事故调查报告出具与批复
一般/较大事故：调查周期不超过30日；重大、特别重大事故不超过60日，复杂情形可延期，延期最长不超过30日。
报告内容：事故概况、损害评估、技术溯源、过错主体划分、责任比例、处罚建议、整改清单、同类风险防控方案。调查报告批复下达后，启动追责执行。
5. 分级追责处置清单
• 行政追责：警告、通报、责令限期整改、罚款、暂停模型服务、吊销备案、吊销审计机构资质；相关责任人约谈、行业禁入。
• 民事追责：依法承担损害赔偿，对受害群体统一救济；
• 刑事追责：涉嫌犯罪，移送司法机关；
• 连带追责：审计、研发、算力服务商存在过错，同步追责。
6. 整改、复测与服务恢复机制
企业提交整改方案，明确整改项、时限、验证指标；整改完成后，必须委托无利益关联的高级资质审计机构复测，复测通过并经监管复核同意，方可恢复高风险AI服务。
整改验收不合格，持续限制服务；同类风险未闭环，禁止上线新模型新版本。
7. 归档与行业复盘
全套卷宗：上报记录、取证快照、测试复现材料、调查报告、批复文件、整改报告、复测报告，完整留存不少于36个月；哈希归档。重大及特别重大事故，组织行业公开复盘，更新法典风险案例库，同步更新审计测试样本集。
五、多方权责
AI运营主体：事故上报、应急止损、证据保全、整改落实第一责任人，不得推诿转嫁主体责任。
模型研发、数据标注、算力服务商：对交付产品固有缺陷承担过错责任。
第三方AI审计机构：审计漏检、报告造假，承担对应连带责任。
事故调查组：客观取证、技术溯源、公正划分责任，独立出具调查报告。
监管机构：受理上报、下达熔断指令、组织调查、批复报告、监督整改验收。
六、禁止性规则
1. 禁止事故发生后，先行修改模型、删除日志、清理证据，掩盖事故诱因。
2. 禁止迟报、瞒报、谎报AI安全事故，人为压缩损害描述。
3. 禁止以“AI自主生成、模型不可控”为由，主张免除主体法定责任。
4. 禁止调查阶段干预审计取证、提供裁剪后的局部测试数据，干扰事故复现。
5. 禁止未完成整改复测，擅自恢复高风险AI对外服务。
6. 禁止篡改、销毁事故取证快照、调查卷宗、哈希存证记录。
七、治理谬误
1. AI自主输出造成损害，属于技术意外，企业无需承担责任。
2. 事故已经修复系统，原始日志可以删除，不影响调查。
3. 第三方审计出具合格报告，发生事故后审计机构无需担责。
4. 权属快照确权等同于事故处置流程合规。
5. 小规模内部测试AI发生事故，免于上报与调查。
全局铁律
AI事故追责遵循先止损、再取证、后定责的固定流程；模型不担责，法人与责任人按过错划分责任；事故节点哈希快照固化原始证据，保障调查可复现；运营主体为第一责任方，研发、算力、审计机构过错连带；事故调查设置时限约束，整改必须经独立第三方复测；未完成风险闭环不得重启高风险AI服务；严禁事后篡改证据、瞒报事故；全卷宗长期归档，事故案例反哺法典风险库，事故追责流程置于法典刚性约束之下。
