# 第115集｜AI开源社区治理规范与风险约束

适用：AI开源仓库、开源社区、模型权重公开发布、分支迭代、PR合并审核、漏洞生命周期管理、开源许可合规、学术开源项目管控。管控开源投毒、后门隐匿、裸发布高风险模型、分支责任逃逸、许可冲突、审核虚化、漏洞处置滞后。本卷优先适用，冲突以此为准，联动法典全部前置基线卷宗，为114模型分发规则的开源专项补充卷。
一、核心定义
AI开源社区为AI代码、数据集、模型权重公开迭代共享生态，兼具创新通道与风险扩散通道双重属性。社区平台主体、项目维护者、下游分支使用者，分层独立担责，安全责任不可转嫁。
社区运营主体：承担平台级审核、违规处置、卷宗留存、漏洞通道运维责任。
项目维护者：承担仓库代码审查、版本安全、合并准入、漏洞初审、发版签名第一责任。
衍生分支：对上游项目实施二次修改独立发布，属于模型重大变更，必须独立风险定级、独立合规，不得继承上游合规资质。
开源许可底线：所有开源协议不得凌驾法典安全基线，不得以开源自由、许可条款豁免备案、测评、漏洞披露义务。
二、分级管控
低风险：纯代码实验仓库，不发布模型权重，留存提交日志，后台抽样审计。
中风险：行业轻量模型开源，设立PR审核与漏洞接收通道，每半年复评。
高风险：基座大模型、公共高风险模型公开开源，强制第三方测评、哈希存证、全链路溯源、季度复评、熔断下架机制，禁止裸开源。
三、底层原则
1. 开源不等于无监管，公开传播必须匹配公开透明安全治理，破除默认信任谬误。
2. 上游承担原生风险披露责任，下游分支承担迭代衍生风险，责任链路完全割裂。
3. 高风险模型无测评、无备案、无安全护栏，禁止公开发布。
4. 所有版本迭代、分支发布、代码合并全程留痕、SHA-256哈希永久存证，抵御供应链投毒与历史篡改。
5. 安全底线不可通过开源协议、学术名义、免费共享规避。
四、全流程核心管控
1. 维护者强制审核标准
所有PR须维护者单人审查方可合并，高风险项目执行双人复核；新增第三方依赖必须做漏洞扫描与许可兼容校验；正式发版必须GPG签名并纳入社区公开密钥目录。
2. 漏洞闭环时限规范
社区常设公开漏洞接收通道，24小时内确认接收；48小时内完成漏洞风险定级；中高风险漏洞72小时内全网公示；高风险漏洞7日内发布修复版本，中风险漏洞30日内完成修复；修复验证后30日内归档完整漏洞卷宗。
3. 开源许可冲突处置
强传染性协议必须显著标注并提示下游商用风险；衍生分支必须保证许可兼容，禁止借分支规避原协议义务；商用授权方式公示透明；许可版本变更需提前90日公示，存量历史版本许可不可追溯修改。
4. 平台与维护者责任边界
社区平台承担平台级合规治理，不对单个项目技术缺陷担责；项目维护者承担项目级全部技术与安全审核责任；平台明知重大隐患不处置，承担连带责任；合规履职后免除项目个体缺陷连带风险。
5. 学术研究豁免规则
纯学术、非商用、不对外服务的开源项目，可简化上架核验，必须明确标注仅限研究用途、禁止商业部署；学术模型一旦转入商用服务，下游必须补全风险定级与备案；学术项目仍强制恪守数据合法合规底线。
6. 版本与分支管控
所有正式发版固化SHA-256哈希永久存证；衍生分支必须主动申报变更、独立重评风险，未申报分支一律判定违规。
7. 熔断机制
检出恶意代码、隐蔽后门、投毒脚本、无备案高风险裸发布、重大漏洞隐匿不报，即刻冻结仓库、下架风险版本、阻断全网扩散、启动全链路溯源整改。
五、多方权责
社区运营主体：平台合规、通道运维、卷宗留存、违规处置全责。
项目维护者：代码合并、版本发版、漏洞初审、版本签名直接责任。
代码贡献者：个人提交内容合规唯一责任。
下游分支与使用者：二次迭代、场景落地、商用转化独立全责。
监管审计：抽查开源合规、版本真实性、漏洞处置时效、分支合规性。
六、禁止性规则
1. 禁止高风险模型无测评、无备案、无安全护栏裸开源发布。
2. 禁止隐匿后门、漏洞、投毒代码，禁止篡改覆盖版本历史与哈希指纹。
3. 禁止以开源自由、开源许可豁免法典安全基线义务。
4. 禁止衍生分支冒用上游合规资质，不申报、不复评风险。
5. 禁止漏洞超时不确认、不定级、不公示、不修复。
6. 禁止学术开源项目隐瞒商用转化，规避合规备案。
七、治理谬误
1. 开源社区自由开放，无需审核监管。
2. 上游合规，下游分支可直接继承合规资质。
3. 开源许可、学术用途可替代安全合规审查。
4. 免费开源无盈利，无需承担风险治理责任。
全局铁律
AI开源生态实行分级治理、分层担责、全程留痕、限时闭环；开源不代表免责，自由不突破底线；高风险模型严禁裸发布，版本哈希永久防篡改防投毒；项目维护者落实刚性审核与漏洞时效机制，平台与项目责任边界清晰割裂；开源许可不得凌驾安全规则，学术开放保留底线豁免；所有分支迭代独立合规定级，杜绝责任逃逸。
