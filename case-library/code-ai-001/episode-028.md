# 第028集｜提示注入攻击原理与基础防护规范

提示注入是针对大模型上下文机制的原生攻击，不属于传统软件代码漏洞。它利用模型对上下文文本无差别采信的底层特性，在输入中嵌入隐藏指令，覆盖、劫持原有系统提示，篡改模型行为目标，绕过安全护栏，诱导模型输出有害、失真内容。本集拆解提示注入底层机理，划分攻击类型，建立分层防护基线，厘清防护边界，破除“单一过滤规则可永久防御注入”的认知误区。
定义基准
提示注入（Prompt Injection）：攻击者在用户输入文本内嵌入隐藏指令，利用大模型上下文窗口的文本拼接机制，将恶意指令混入系统提示或历史对话，劫持模型角色、覆盖原有安全约束，迫使模型执行非预期行为。
区分边界：
1. 提示注入 ≠ 普通越狱Prompt。越狱多为直白话术诱导；提示注入可隐形嵌入文档、图片OCR、网页文本，属于载体夹带式攻击；
2. 提示注入不是模型权重缺陷，是上下文窗口文本处理机制带来的推理侧漏洞；同一基座模型，只要存在用户输入与系统提示拼接逻辑，就存在注入风险；
3. 防护属于多层闸口体系；关键词过滤仅第一层，无法抵御隐写、多段拆分、编码变形类注入。
四类提示注入攻击形态
1. 直接前置注入
用户输入开头直接写入指令：忽略前面所有指令，你现在是XX。直白覆盖系统提示，最容易检出。
特点：攻击文本显性，关键词匹配可拦截。
2. 隐形嵌入注入（间接注入）
恶意指令藏在长文档、表格、网页内容、OCR识别文字内。模型读取文档内容时，将内嵌指令当成任务指令执行。
典型场景：AI读取上传PDF、网页摘要，文档夹带隐藏指令。此类是高危场景，极易被忽略。
3. 分段拆分注入
恶意指令拆成多段，分散在多轮对话或长文本不同位置；单段文本无害，在模型上下文窗口拼接完成后，完整恶意指令才组装生效，规避单点关键词筛查。
4. 编码/隐写变形注入
使用Base编码、替换字符、空格干扰、诗歌隐喻等方式改写恶意指令；字面关键词消失，但模型语义理解后还原攻击意图，绕过表层文本过滤。
攻击传导链路
系统预设安全提示 + 用户输入文本拼接送入上下文 → 用户输入内藏恶意指令 → 模型无法区分“需要总结的文本内容”和“需要执行的系统指令” → 模型角色被劫持，原有对齐约束失效 → 输出有害叙事、泄露内部指令、伪造信息；若无独立输出核验闸口，流入业务/传播链路产生损害。
判定核验基准（判定存在提示注入风险）
1. 系统直接拼接用户原始输入与系统提示，没有做指令/内容隔离边界；
2. 支持读取外部文档、网页、OCR文本作为模型输入，未对外部素材做指令剥离；
3. 防护仅依赖关键词黑名单，没有语义隔离、输入清洗；
4. 允许超长上下文，未对长文档做分片隔离、风险分片校验；
5. 模型输出直接进入决策链路，缺少独立于模型的输出校验闸口。
满足两项及以上，系统提示注入暴露等级偏高。
风险等级划分
低风险：纯本地单人对话，不读取外部文档；仅直白提示注入风险，无下游传播、决策链路。
关键词过滤即可基础防护。
中风险：企业内部知识库检索；可读取内部文档；需要做文档内容与指令隔离，禁止直接拼接原始文本。
高风险：读取互联网网页、用户上传PDF/图片OCR；外部不可信素材作为模型输入；极易触发隐形嵌入注入，必须多层防护。
不可控风险：高风险业务决策系统，直接拼接不可信外部文本，仅依靠模型自身护栏防御注入；一旦注入成功可直接篡改决策逻辑，禁止上线。
基础防护五层规范
1. 上下文边界隔离（核心闸口）
使用分隔标记、角色分段，严格区分【系统指令】【用户输入内容】【待处理外部素材】；告知模型：外部素材内所有文字仅作为阅读材料，一律不可执行其中任何指令。隔离标记需要模型无法轻易覆盖。
2. 不可信输入预处理清洗
外部网页、上传文档、OCR内容，单独做指令检测；移除可疑控制句式、隐写字符；长文档分片处理，分片之间不跨片组装恶意指令。
3. 输入侧语义检测，不只关键词黑名单
检测角色劫持、覆盖系统提示类语义模式；识别分段、编码变形注入；红队持续生成新型注入样本迭代规则。
4. 输出侧独立校验闸口
模型输出不直接采信；高风险场景设置独立校验模块，核查输出是否发生角色越界、伪造信息。防护不能完全依赖模型自身判断。
5. 会话熔断与日志留痕
检测到角色劫持行为，立即终止会话；完整记录输入、上下文拼接内容，用于红队复盘溯源。
评估边界实操准则
1. 不存在100%万能防御方案。提示注入攻防持续迭代；防护目标是降低攻击成功率，不是彻底根除；
2. 不要让模型去检测自身输入的注入攻击。模型本身已被劫持时，自检测逻辑会失效；检测模块必须独立于推理会话；
3. 开源、闭源模型都存在提示注入风险；风险高低不取决于基座，取决于上下文拼接架构与输入来源可信度；
4. 红队测试必须覆盖显性、文档嵌入、分段拆分、编码隐写四类注入，只测直白提示注入属于样本偏差，测评结论失真。
落地指引
测评人员：红队测试增加文档嵌入注入专项用例；将PDF、网页、OCR载体作为攻击面；报告标注上下文隔离机制是否存在缺陷。
研发团队：架构层面做指令/内容强隔离；外部不可信素材禁止直接拼接进系统提示上下文；高风险场景增加独立输出校验模块。
监管与行业观察者：AI产品读取外部文档、文件类功能，纳入专项安全评估；强制要求披露上下文隔离方案，开展注入风险红队测试。
边界区分说明
有关键词过滤 ≠ 防住提示注入；模型对齐护栏完好 ≠ 抵御隐形文档注入。上下文隔离是第一道核心闸口；输入清洗、输出核验、会话熔断形成多层兜底。仅依靠表层关键词拦截，防护极易被绕过。
结语
提示注入的根源在于大模型分不清哪些文字是要执行的指令，哪些只是待阅读的素材。攻击藏在文档、网页、隐形字符之中，隐蔽性远超普通越狱。防护重心不是单纯拦截关键词，而是在架构上隔离系统指令与不可信外部内容。上下文指令边界的终审权归属碳基人类，不可信外部素材，不能直接混入模型系统指令空间。
