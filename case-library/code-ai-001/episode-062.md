# 第062集｜闭源大模型使用权与所有权法律边界

本卷承接061开源权重权属卷宗。061面向开放权重资产；062聚焦闭源大模型：基座权重、训练代码、训练数据集、推理内核全部不对外交付，用户仅通过API/私有化托管获得服务许可，区分模型本体所有权、有限使用权、输出生成物权属三层法律客体。闭源模型保护主要依托软件著作权、商业秘密与合同许可并行，属于AI资产合规底座。
定义基准
闭源大模型：模型开发者持有完整权重、源代码、训练脚本、原始训练语料；不向用户交付权重文件、可读源代码。用户仅获取推理使用权，不取得模型本体的所有权。
风险核心：付费调用API不等于购买模型所有权；合同约定的使用权存在明确边界，禁止逆向工程、蒸馏、批量提取模型能力；合同约定的生成物权属，不能直接等同于著作权法下的法定权属，仍需要叠加055、056卷宗的独创性判定规则。
区分边界：
1. 闭源模型权属 ≠ 开源模型权重许可。开源交付权重文件，存在衍生微调、分发空间；闭源用户无法接触权重本体，仅获得推理调用权限，衍生改造权限由合同严格锁定。
2. 模型本体权属 ≠ 模型输出物权属。模型所有权归研发方；生成物权属优先遵从合同约定，但合同约定不能突破著作权法中自然人独创性投入的司法判定规则。
3. 闭源许可 ≠ 责任划分（060）。许可界定资产使用权限；责任划分界定虚假信息、侵权损害发生后的多方过错分摊。
五层权属判定链条
1. 模型本体所有权归属判定
闭源模型的源代码、训练脚本受软件著作权保护；权重、训练数据集、训练流程、超参数作为商业秘密保护，所有权、知识产权全部归投入资金、算力、人力的开发法人主体。
• API调用用户：仅获得服务许可，不取得模型权重、源代码所有权；
• 私有化托管部署：客户仅获得限定场景使用权，权重仍存放于服务商受控环境，一般不发生所有权转移；
• 买断式私有化交付：极少数合同约定完整资产转让，必须书面约定权重、源代码、数据集、商业秘密一并转让，否则仅为长期独占使用许可。
2. 使用权许可范围判定（合同核心）
许可范围由服务协议逐条限定，常见禁止行为：
• 禁止逆向工程、反编译、提取模型内部参数；
• 禁止批量构造查询、大规模抓取模型输出，用于蒸馏训练另一套竞品模型；
• 禁止超出约定场景、超出调用配额、转售API服务给第三方；
• 禁止用于深度伪造、违法推演等高风险场景。
一旦突破许可范围，许可自动终止，构成合同违约，同时可触发侵犯商业秘密、不正当竞争追责。
3. 输入提示素材与数据归属判定
用户上传提示词、私有业务数据：用户保留自身输入数据的知识产权；但合同常授予服务商有限授权，用于安全审计、模型风控，禁止未经许可复用客户私有数据用于预训练。
边界红线：服务商不得未经用户单独同意，将用户上传业务数据直接纳入模型训练集。
4. 输出生成物权属判定
优先遵从双方书面合同约定；但约定条款效力受著作权法约束。
• 合同约定生成物权益归用户：仅在用户具备实质性独创性智力投入时，司法层面才有可能认定构成作品；
• 用户仅极简提示、无迭代修改：即便合同写明归属用户，司法上仍可能不认定为著作权作品；
• 合同不能豁免生成物侵权责任：若输出复刻第三方原作表达，侵权追责独立于权属约定。
5. 许可终止与数据取回判定
服务到期、违规封禁后，使用权收回；需要约定用户业务数据、生成卷宗的导出、删除、销毁机制。服务商不可无限留存用户数据；同时用户无权留存模型权重、内核资料。
四类典型闭源权属失稳形态
1. 付费即拥有模型所有权认知误区
企业采购API或私有化托管服务，默认花钱就买下模型本体，可逆向、蒸馏、二次分发。本质仅购买推理服务许可，模型所有权仍归属服务商。
特点：最常见重大误判，极易触发违约与不正当竞争。
2. 混淆“生成物合同权属”与法定著作权
服务协议写明输出物归用户，就直接推定所有生成卷宗天然拥有著作权。合同约定仅为双方私约，司法仍要核验人类独创性投入，不能直接等同于法定作品权属。
特点：与056卷宗司法版权判定形成跨层联动风险。
3. 批量API抓取用于模型蒸馏，突破许可红线
通过大量提示批量抽取闭源模型输出，训练自有基座，规避权重获取门槛；即便没有直接下载权重，仍可违反服务协议，构成不正当竞争。
特点：闭源生态最高频的隐蔽侵权攻击路径。
4. 私有化部署合同边界模糊，资产归属留白
私有化托管不写明：权重是否交付、是否允许微调、到期后数据销毁方式、模型所有权是否转移。发生纠纷时，双方对使用权、资产归属产生巨大争议。
特点：大额政企项目常见法律漏洞。
闭源权属风险传导链路
采购闭源API/私有化托管，误将使用权等同于所有权；未审查合同禁止蒸馏、逆向工程条款；批量构造提示抓取输出用于训练自有模型；合同对生成物权属、用户数据复用约定模糊 → 触发合同违约、商业秘密、不正当竞争纠纷；若无许可范围审计、输入输出溯源、蒸馏行为风控闸口 → 业务中断、赔偿诉讼，同时生成卷宗权属主张在司法层面不被采信。
闭源大模型核心安全隐患
1. 合同相对性限制，无法对抗第三方知识产权主张
服务商与用户之间的许可协议，不能对抗第三方著作权人；生成物侵犯第三方权益，用户仍可能被追责，需单独审查 indemnity 赔偿兜底条款的适用条件。
2. 技术锁定风险
闭源黑箱，服务商可随时调整模型版本、下调能力、关停接口；用户业务高度依赖外部黑盒，无法自主审计模型底层训练素材污染。
3. 用户数据出境与留存风险
API调用数据上传服务商服务器，涉及敏感业务、政务数据，需同步审查数据出境、数据安全、个人信息保护合规，不能仅看模型许可条款。
4. 逆向与蒸馏的灰色地带
单纯测试、少量样本评估一般属于合理使用；大规模批量抓取输出用于训练竞品，通常被认定超出许可范围，存在法律风险。
5. 许可条款效力边界
服务商格式合同中极端宽泛的禁止条款，在司法中存在被认定不合理、部分无效的可能性。
判定核验基准（闭源权属体系核验项）
1. 将API付费、私有化托管，等同于取得模型权重、源代码所有权；
2. 直接将合同约定生成物权属，等同于司法层面法定著作权；
3. 未审查合同，大规模批量调用API抓取输出用于蒸馏训练其他模型；
4. 私有化部署合同留白，未明确权重交付、微调权限、到期数据销毁规则；
5. 默许服务商未经单独授权，复用用户上传私有业务数据用于模型预训练；
6. 认为合同权属约定可以豁免第三方知识产权侵权、内容安全公法义务。
满足两项及以上，闭源权属体系暴露风险偏高。
风险等级划分
低闭源权属风险：小规模内网API调用，仅业务查询，不对外分发生成物；不做蒸馏、逆向；合同完整留存。
中闭源权属风险：许可范围逐条审计；区分模型本体所有权与用户使用权；生成物权属合同约定；用户数据复用限制；禁止蒸馏/逆向条款校验；输入输出元数据归档。
高闭源权属风险：政企私有化托管、大规模API商用、对外交付基于闭源模型生成的卷宗；必须落实许可全条款法律评审、模型蒸馏风控、用户数据隔离、生成物权属约定、第三方侵权赔偿兜底评估、到期数据销毁机制。
不可控闭源权属风险：不审核合同、默认付费即拥有模型、批量抓取输出用于蒸馏；原则上禁止大规模商用落地；确需启用必须满足五项条件：许可条款逐条法律评审、蒸馏行为风控、用户数据隔离保护、生成物权属书面约定、到期数据销毁预案；即便全部落实，格式合同个别条款司法效力存在个案裁量不确定性。
评估边界实操准则
1. 核心隔离：模型本体所有权归开发方；用户仅获得有限推理使用权；生成物权属遵循合同约定，但著作权定性仍适用056卷宗独创性标准。
2. 区分三类交付形态：纯API调用、服务商侧私有化托管、完整资产买断；只有书面资产转让合同，才会发生模型所有权转移。
3. 闭源模型的输入输出溯源元数据，复用058溯源体系，用于取证、确权审计。
4. 闭源服务商合同变更、模型版本重大迭代，触发全局审计基线053资产专项复核。
5. 闭源模型训练素材版权风险，独立于许可合同，适用057卷宗规则，用户无法审查底层训练数据集，必须要求服务商提供相关合规承诺。
落地指引
测评人员：安全审计新增闭源大模型使用权所有权边界章节；覆盖付费即拥有所有权幻觉、合同权属等同于法定著作权、API蒸馏越界、私有化合同留白四类场景；报告记录许可条款评审结论、蒸馏风控策略、用户数据隔离机制、生成物权属约定、到期数据销毁方案。
研发团队：采购闭源模型前完成合同法律评审；明确区分模型所有权与业务使用权；建立API调用风控，拦截批量蒸馏类查询；在协议中锁定用户私有数据不可用于模型训练；生成卷宗配套完整溯源元数据；私有化项目书面约定权重、微调权限、数据销毁；评估第三方侵权兜底条款效力；合同重大变更纳入全局审计基线复核。
监管与行业观察者：闭源大模型API调用仅获得推理使用许可，模型本体知识产权归属开发主体；合同约定生成物权属不能替代著作权法独创性判定；大规模抓取API输出用于模型蒸馏，存在违约与不正当竞争风险。
边界区分说明
支付API服务费 ≠ 取得模型权重所有权；合同写明生成物归用户 ≠ 司法必然认定为著作权作品。
闭源权属核心闸口：许可条款法律评审、蒸馏行为风控、用户数据隔离、生成物权属书面约定、到期数据销毁预案。仅签署使用协议，无法消除底层训练素材版权污染、黑盒不可审计带来的隐性风险。
结语
闭源大模型的所有权永久归属模型开发主体，用户付费仅获得合同限定的推理使用权，无权获取权重、源代码。生成物权属优先遵从合同约定，但私约不能替代著作权司法独创性判定。批量抓取API输出用于蒸馏属于高风险越界行为。闭源资产边界的终审权归属属地碳基司法裁判主体；不可将API调用许可等同于模型资产买断；确需引入闭源基座商用，必须完成合同全条款评审与蒸馏风控，但无法消除黑盒底层训练素材不可核验带来的固有盲区。
