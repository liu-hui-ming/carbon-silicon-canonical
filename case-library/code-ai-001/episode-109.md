# 第109集｜大模型市场准入机制与安全备案规范

适用：基础大模型、微调衍生模型、对外提供服务的大模型应用，规范上线准入、安全评估、备案变更、持续监测、下线注销全流程。管控：跳过安全评估直接上线、备案材料造假、模型迭代不更新备案、基础模型缺陷向下游传导、备案后长期不开展复审、境外模型无合规准入。
本卷优先适用，冲突以此为准，联动058确权卷宗、105风险分层卷宗、106例外校准卷宗、107全行业统一基线卷宗、108术语口径卷宗、模型生命周期卷宗。
一、核心定义
大模型市场准入：大模型及配套服务对外提供访问、调用、商用前，完成风险定级、安全测评、备案登记的前置流程，未完成准入不得面向公众开放服务。AI仅为推演辅助工具，准入申报、备案维护、风险处置权责归属场景运营主体，责任不得转嫁AI、模型研发厂商。
基础模型：具备通用能力，可经微调、提示词工程衍生大量下游应用的预训练大模型，风险具备传导性，准入管控强度高于单一场景微调模型。
模型变更触发备案：模型权重更新、训练数据集大规模替换、能力边界显著扩展、服务范围扩大、风险等级上调，属于重大变更，必须重新提交安全评估与备案更新。
分级管控
L1：内部离线实验模型，不对外提供接口与公开服务，仅留存基础研发日志，无需对外备案，后台抽样审计。
L2：限定行业、封闭用户群体的大模型应用，不具备广泛舆论动员能力；完成安全评估，提交备案，每半年开展一次风险复评。
L3：面向公众、具备舆论传播或社会动员能力，用于关键基础设施、政务、医疗、金融等高风险领域的大模型；必须独立第三方安全测评，完成备案登记，每季度开展风险复评，强制部署熔断与独立兜底链路。
准入备案卷宗：风险定级报告、安全评估报告、模型哈希快照、训练数据溯源材料、对抗测试报告、熔断与兜底链路验证记录、备案申请表、变更记录、复审材料、事件处置记录；最低保存3年，L3大模型安全事故、系统性缺陷、大规模内容风险案例永久归档。
永久归档清单：模型SHA-256哈希快照、完整安全评估报告、对抗攻击与红队测试记录、训练数据集溯源清单、历次备案变更材料、风险复评报告、安全事件时序日志、下线注销复盘文档。
熔断机制：备案运行期间检出模型漂移、大规模幻觉、提示注入漏洞、数据泄露、越权输出，立即收缩服务权限，限制接口调用，启动兜底管控；L3场景触发重大风险告警，暂停对外服务，直至完成整改复测。
准入基线：准入必须遵循法典统一L1/L2/L3分级规则，术语释义以108卷宗为准；准入测评不得降低法典底层刚性安全底线，仅可叠加行业专项约束。
二、底层原则
1. 先评估、后备案，未完成备案不得对外提供大模型服务；准入主体为场景运营主体，模型研发厂商承担模型原生风险披露义务。
2. 基础模型风险向下游传导，下游应用选型接入基础模型时，同步核验基础模型准入备案卷宗，不得接入未完成准入的基础模型。
3. 分级准入，就高从严；只要存在公共舆论、人身安全、国家安全任一要素，直接判定L3，执行最高强度准入管控。
4. 动态备案，模型发生重大变更必须更新备案；业务、规模、数据源变更触发风险重评，复审不通过暂停对外服务。
5. 准入不代表永久合规，准入仅证明上线时点满足基线，运行期间持续监测、定期复审，风险恶化可启动备案撤回与服务下线。
6. 例外场景严格遵循106卷宗规则，L3大模型常规业务不开放例外，仅应急救援场景启用限时临时例外，底线条款不可豁免。
三、全流程管控
1. 准入前置评估：上线前执行法典风险三要素评估，确定风险等级；L3大模型必须第三方独立安全测评，开展红队对抗、提示注入、数据投毒、幻觉边界测试，验证熔断、兜底链路有效性。
准入材料清单：主体资质、模型版本SHA-256哈希、训练数据来源与脱敏证明、内容安全护栏说明、越权指令拦截机制、日志留存方案、应急处置预案、风险定级报告、安全评估报告。
2. 备案登记流程：材料核验通过后完成备案登记，分配唯一备案编号；备案编号随对外接口、服务页面公示，供审计核验。
3. 变更与复审机制：模型权重、训练数据集、服务范围、风险等级发生重大变更，30日内提交变更备案。L1每年复审；L2每半年复审；L3每季度复审。复审不通过，限期整改，整改期间限制服务规模；逾期未达标，注销备案。
4. 境外模型准入：境外大模型向境内提供服务，执行同等准入、安全评估、备案要求，不得豁免；必须满足境内数据留存、日志审计、安全事件上报规则。
5. 接入管控：下游应用调用第三方基础模型接口，核验基础模型备案卷宗与版本哈希；接入未备案模型，视为运营主体准入不合规。
6. 下线注销：永久停止服务，提交注销备案，留存完整卷宗；模型销毁、权重封存记录纳入归档材料。
7. 熔断处置：运行期间触发安全告警，收缩接口权限，暂停开放能力，溯源定位缺陷；整改完成并复测通过，方可恢复对外服务。
四、多方权责
1. 场景运营主体：准入申报、备案维护、定期复审、安全监测、事件上报、卷宗保管第一责任人。
2. 模型研发厂商：提供模型哈希、训练数据溯源、原生风险清单、漏洞更新说明，不得隐瞒模型固有缺陷，不得协助运营主体伪造备案材料。
3. 独立安全测评方：开展大模型安全评估、红队对抗测试，出具客观测评报告，对测评记录归档。
4. 监管审计方：核验备案卷宗、抽查模型版本哈希、复审记录，核查模型变更未申报、材料造假等违规行为，责令暂停服务或注销备案。
五、确权交叉规则
模型训练脚本、权重衍生代码、安全测评脚本归入数据保护层；治理专家设定准入分级、备案变更、复审注销逻辑重构触发权属快照，独创性部分纳入著作权保护层。
备案卷宗、安全评估报告、复审记录、注销材料不适用快照确权。权属快照仅判定成果归属，不可替代准入安全评估与备案合规审查，不免除运营主体准入备案责任。
六、禁止性规则
1. 禁止将准入备案、安全处置责任转嫁AI、模型厂商。
2. 禁止跳过安全评估直接提交备案，禁止伪造测评报告、数据溯源材料、模型哈希。
3. 禁止L3大模型不完成第三方测评、不部署熔断兜底链路直接申请准入。
4. 禁止模型重大变更不申报变更备案，沿用旧备案持续对外提供服务。
5. 禁止下游业务接入未完成准入备案的基础大模型。
6. 禁止境外模型在境内提供服务豁免准入评估与备案。
7. 禁止备案通过后关闭日志审计、熔断告警机制。
8. 禁止删除篡改模型哈希快照、安全测评记录、备案变更、复审卷宗。
七、治理谬误
1. 模型仅为内部研发，少量对外测试，无需备案谬误。
2. 基础模型已经备案，下游微调应用无需重复风险评估。
3. 备案审批完成即永久合规，后续模型迭代无需复审。
4. 权属快照确权等同于大模型准入备案合规。
5. 临时试用、小范围内测，可申请永久例外免除备案。
全局铁律
大模型执行先评估后备案，运营主体承担准入与持续安全全责；分级准入就高从严，L3大模型强制第三方测评、熔断与兜底链路；模型重大变更必须更新备案，按期复审，复审不通过暂停服务；下游接入基础模型须核验备案与版本哈希；境外模型准入标准与境内模型保持一致；权属快照区分成果归属，不可替代大模型准入安全评估与备案审查义务。
