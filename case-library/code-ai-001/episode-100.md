# 第100集｜交通AI调度系统安全冗余与风险管控

适用：城市信号配时、路网流量调度、公共交通排班、自动驾驶路侧协同AI系统。管控：模型漂移、极端工况误调度、单点故障连锁拥堵、指令越权、感知幻觉、数据篡改。本卷优先适用，冲突以此为准，联动058确权卷宗、模型生命周期卷宗。
一、核心定义
交通AI调度系统：流量研判、信号配时方案、公交排班、路网预警辅助工具。AI仅输出调度备选方案，交通管控、信号强制干预、应急处置最终决策权归交管运维主体，责任不得转嫁AI或模型厂商。
交通感知幻觉：AI误识别车流、行人、事故，输出错误配时、疏导方案。
分级管控
L1：路网流量统计、趋势监测、报表生成，只读分析，后台抽样审计。
L2：常规时段信号配时、公交排班优化建议，方案落地前人工复核。
L3：重大事故、恶劣天气、大型活动应急调度，AI仅提供态势参考，禁止自动下发强干预指令，强制人工终审，冗余备用系统待命。
交通调度卷宗：路网原始感知数据、AI调度方案、人工审批记录、故障告警、应急处置日志；最低保存2年，重大事故、群体性拥堵案例永久归档。
永久归档内容清单：事故发生前后30分钟路网原始感知数据、AI调度方案及版本号、人工审批记录、熔断触发日志、兜底链路切换记录、应急处置全过程指令流、事后复盘报告。
熔断机制：感知异常、方案越界、模型漂移超标，AI自动退出闭环控制，切换至人工固定配时兜底模式。
模型漂移超标判定：调度方案与实际路况匹配度连续7日低于80%、AI推荐方案采纳率连续3日低于60%、同一类感知误判事件单日累计超50次，满足任一条件即触发熔断。
双冗余基线：AI调度系统必须配套独立传统固定控制兜底链路，AI失效时无缝切至人工备用链路。
切换时限规范：AI退出闭环控制后，系统应在3秒内自动切换至传统固定配时兜底模式；切换期间信号灯保持最后一组有效配时或切换至黄闪警示状态，禁止信号灯熄灭或全红锁死。
二、底层原则
1. 交通管控主权归属交管运维方，AI仅方案辅助，高危应急场景禁止AI自主强干预。
2. 系统必须建设独立冗余兜底链路，AI不可作为唯一控制源。
3. 风险越高，AI调度权限越受限，人工终审要求越强。
4. 全链路感知、指令、审批留痕，事故可回溯复盘。
5. 常态化模型校验，定期压力测试极端工况。
三、全流程管控
1. 架构准入：AI调度不可替代传统控制链路，部署双冗余兜底。
2. 感知输入：多源传感器交叉校验，单一传感器异常时自动降权。
交叉校验逻辑：采用时空对齐后的一致性检验机制；同一目标至少两个独立传感器（摄像头+雷达/激光雷达）同时检出且位置偏差在阈值范围内方可采信；单一传感器检出、其余传感器未检出目标标记为低置信度并降权。
3. 分级执行：L1仅监测统计；L2配时方案人工复核；L3应急场景AI只做态势展示，不自动下发管控指令。
4. 压力测试：暴雨、事故、大流量等极端场景定期仿真测试，验证熔断切换可靠性。
测试频率：极端工况压力测试不低于每季度1次；重大节假日、大型活动前开展专项仿真测试；覆盖暴雨、大雾、冰雪、重大交通事故、大型活动散场、主干道封闭等不少于5类典型极端场景，测试报告存入卷宗备查。
5. 熔断处置：检出幻觉、漂移、通信异常，退出AI自动调度，切换人工兜底模式，启动模型核查。
四、多方权责
1. 交管/运维主体：调度方案终审、冗余架构运维、应急处置第一责任人。
2. 模型厂商：披露模型边界、极端工况风险，不承诺全天候调度绝对可靠。
3. 集成商：落地冗余链路、交叉校验、熔断切换机制。
4. 监管审计方：抽查卷宗，核查冗余机制与应急切换有效性。
五、确权交叉规则
AI原生流量分析、配时方案脚本归入数据保护层；交通专家设定安全约束、冗余切换逻辑重构触发权属快照，独创性部分纳入著作权保护层。
调度日志、审计卷宗不适用快照确权。权属快照仅判定成果归属，不可替代交通安全校验，不免除交管运维主体安全责任。
六、禁止性规则
1. 禁止将交通调度安全责任转嫁AI、模型厂商。
2. 禁止撤除传统兜底链路，把AI作为唯一交通控制源。
3. 禁止L3应急场景由AI自动下发强干预管控指令。
4. 禁止单传感器数据直接驱动AI调度，缺少交叉校验。
5. 禁止屏蔽漂移与感知幻觉告警，在异常状态持续运行AI调度。
6. 禁止删除篡改调度方案、审批痕迹、应急处置卷宗。
七、治理谬误
1. 日常工况运行稳定，无需冗余兜底链路谬误。
2. AI输出配时方案合理，可省略人工复核。
3. 权属快照确权等同于调度系统满足交通安全标准。
4. 极端场景可交由AI自主完成应急处置。
全局铁律
交通AI仅输出调度备选方案，交管运维承担交通安全全责；系统强制部署独立冗余兜底链路，高危应急场景禁止AI自动干预；感知信息交叉核验，异常触发熔断切人工模式；严格执行定时极端工况压力测试；全链路留痕复盘；权属快照区分成果归属，不可豁免交通调度安全审查义务。
