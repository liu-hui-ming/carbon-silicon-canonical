# 第125集｜政府采购AI系统准入安全标准

适用：政务审批、公共资源分配、公共服务、政务辅助决策、公共安防、医保风控等政府采购AI项目，包含定制开发模型、API模型调用、本地化部署、云服务托管模式。管控投标阶段隐瞒模型缺陷、合同权责模糊、交付验收流于形式、供应商远程无管控迭代、数据权属不清、事故责任互相推诿、采购评审忽略AI安全指标。本卷优先适用，冲突以此为准，联动全部前置卷宗；承接124公共领域算法公开与脱敏边界卷宗，上一卷划定公共算法披露边界，本卷构建采购立项、招标评审、合同约束、交付验收、运维迭代、退出移交全链路准入安全管控体系。
一、核心定义
政府采购AI系统：由财政资金采购，部署于公共治理场景，用于公共事务处理、资格判定、资源分配、辅助决策的AI模型与配套软硬件。AI仅为推演辅助工具，采购需求编制、招标评审、验收核验、运维监管权责归属采购人；供应商承担模型原生缺陷、数据合规、安全防护的直接责任。
准入安全基线：法典强制最低安全门槛，所有政府采购AI项目不得低于该基线，高风险场景须追加增量安全要求。
模型迭代锁控：供应商不得未经采购人书面审批，远程修改模型权重、特征集、决策阈值；重大版本变更必须前置第三方审计。
移交与退出机制：合同到期、项目终止、供应商更换时，完成模型、数据、文档、审计底稿完整移交，保障公共业务连续运行。
二、分级管控
低风险政府采购AI：公共信息检索、文本辅助润色、咨询问答，仅作辅助参考；立项阶段提交基础安全自查，年度复核。
中风险政府采购AI：公共预约、排队调度、基础材料初审；招标阶段提交安全评估报告，中标后开展第三方预审，半年安全抽检。
高风险政府采购AI：救助资格审核、医保智能风控、公共准入、资源分配、公共安防决策；立项前置风险评审，招标必须附带高级资质审计机构出具的安全鉴证；交付前全量灰盒审计，季度安全复测。
三、底层原则
1. AI安全指标为硬性准入门槛，不得仅以价格、基础功能作为评标核心依据；安全不达标直接否决投标资格。
2. 采购人保留业务主导权，AI仅作为辅助工具，最终公共决策必须保留人工复核通道，高风险事项禁止AI全权自动裁决。
3. 权责写入合同固化：模型缺陷、数据泄露、算法偏见、事故损害，按过错划分采购方、供应商、第三方审计机构责任，不得预先免除供应商法定责任。
4. 数据权属归公共采购主体，供应商仅拥有服务使用权，禁止将政务敏感数据挪用于模型二次训练、对外商用。
5. 模型迭代受审批管控，重大版本变更必须审计备案；合同终止必须完成完整移交，防止供应商锁死模型、技术绑架公共业务。
四、全流程核心管控
1. 立项阶段前置风险评估
采购立项前，采购人委托持证审计机构开展风险分级判定，明确风险等级、法典强制安全清单、脱敏公开要求。高风险项目必须提交风险评估报告，未通过评估不得进入招标流程。
立项文档写明：场景边界、禁止自动决策清单、人工兜底机制、数据分类、保密等级、事故熔断触发条件。
2. 招标评审硬性准入指标
投标文件必须附带全套材料：模型来源证明、训练数据集合规审计报告、偏见测试报告、安全对抗测试记录、迭代管控方案、事故应急处置预案。
评标设置安全否决项，出现以下情形直接废标：① 模型未完成法定备案、无安全评估；② 训练数据来源不合规，存在版权、个人信息侵权；③ 算法偏见量化指标突破法典红线，群体通过率差异超过15%；④ 无人工兜底机制，高风险场景设置全自动决策。
3. 采购合同强制约定条款
合同必须固化以下条款：① 数据权属：项目产生政务数据归采购人，供应商不得私自导出、复用；涉密数据不得输出至外部模型；② 模型迭代审批：重大特征、阈值、权重变更必须书面申请+第三方审计通过后方可上线；轻量化性能优化仅留痕报备；③ 事故责任划分：因模型原生缺陷、安全防护缺失引发AI事故，供应商承担对应过错责任；④ 交付移交清单：源码、配置、训练索引、归因接口、审计底稿、运维手册；⑤ 退出保障：合同到期或终止，供应商必须移交全部可运行系统与文档，不得设置技术锁，开放灰盒审计接口；⑥ 质保期不低于24个月，质保期内免费完成安全漏洞修复。
4. 交付验收与第三方审计核验
交付验收前，必须由与供应商无利益关联的持证审计机构完成独立核验，验收核验项：① 模型实际运行逻辑与投标文档一致；② 偏见、对抗注入、越狱攻击、数据泄露风险达到准入基线；③ 灰盒归因接口可用，满足公共算法脱敏披露要求；④ 人工复核通道完整，熔断机制可正常触发；⑤ 全套卷宗、哈希快照完整留存。
审计不通过，不予验收、不予支付尾款，限期整改，整改两次仍不合格，解除采购合同。
5. 运维与版本管控
项目上线运行后，按风险等级定期审计抽检；高风险项目每季度复测。
供应商推送模型更新，区分两类变更：
• 重大变更（特征集、决策阈值、基础模型基座）：提交申请、第三方审计、采购人审批，30日内同步更新公共脱敏公开文档；
• 微小性能优化：仅内部日志留痕，无需公开更新。
运维全程推理日志、操作记录哈希存证，日志留存不少于36个月。
6. 项目终止、供应商更换移交规范
合同到期、项目下线、更换服务商，执行移交核验：① 模型、配置、接口、全套文档完整交付；② 供应商端删除全部政务敏感原始数据，出具数据销毁证明；③ 移交后仍保留保密义务，不得泄露公共业务算法与敏感信息；④ 移交完成后，由第三方审计核验移交完整性。
7. 熔断机制
检出投标材料造假、模型实际能力与标书严重不符、未审批私自迭代模型、数据被挪用训练、高风险场景取消人工兜底、验收审计造假，立即暂停项目支付，暂停AI系统运行；限期整改，情节严重解除采购合同，供应商列入政府采购黑名单，同步追责。
五、多方权责
采购人：立项风险评估、招标安全评审、验收组织、日常监管第一责任，不得降低法典安全基线。
AI供应商：模型安全、数据合规、缺陷修复、迭代报备、项目移交、事故损害的直接责任主体。
持证AI审计机构：独立开展立项评估、交付验收、定期复测，对审计结论真实性负责。
政府采购监管部门：核查采购全流程合规性，核验安全准入条款落实，处置供应商失信与合同违约。
六、禁止性规则
1. 禁止政府采购AI项目，将价格作为首要评审权重，忽略法典安全准入基线。
2. 禁止高风险公共AI场景取消人工复核，设置全自动决策。
3. 禁止供应商未经采购人书面审批，私自远程修改模型核心参数。
4. 禁止供应商将采购项目内政务、民生敏感数据挪用于外部模型训练。
5. 禁止交付验收跳过第三方独立安全审计，直接上线运行。
6. 禁止供应商设置技术壁垒、拒绝项目终止时移交系统与卷宗。
七、治理谬误
1. 中标产品拥有厂商内部安全认证，即可豁免法典政府采购准入审计。
2. 采购合同可预先约定免除供应商模型缺陷导致事故的赔偿责任。
3. 云API托管模式，数据安全与算法责任全部由云厂商承担，采购人无监管义务。
4. 权属快照确权等同于政府采购AI项目准入合规。
5. 低风险辅助AI采购项目，可省略立项风险评估。
全局铁律
政府采购AI项目以法典安全基线作为硬性准入门槛；立项前置风险分级，招标设置安全否决项；合同固化数据权属、迭代审批、事故责任、退出移交条款；交付必须经过独立第三方审计核验；高风险场景强制保留人工兜底，禁止全自动裁决；模型重大变更必须审批审计；项目终止保障业务移交，杜绝技术锁死；采购全流程卷宗哈希归档；供应商造假、私自迭代、挪用敏感数据触发熔断与黑名单惩戒，政府采购AI准入置于法典刚性约束之下。
