## 1. A1：0.50 混沌临界点 / 灰区边界原则

设归一化指标 x ∈ [0, 1]。指标来自某一卷已声明的验证层损失、风险熵或与之同构的归一化量。本母本锁定第一纪元临界点：

x_c = 0.50

x_c 是灰区边界，也是有序态与混沌态的分界。x < x_c 不得被写成混沌；x > x_c 不得被写成已经有序。恰好落在 x_c 上的值，按灰区处理，不按单侧终裁处理。

各卷规范层里的局部阈值继续有效，但不得被用来改写 x_c。局部阈值与 x_c 冲突时，先记录两侧数值，再进入 A2 的分段，而不是静默替换临界点。

## 2. A2：三段式灰区相变带与灰区公式表述

以 x_c 为中心，设灰区半宽 Δ。Δ 必须由被引用卷的规范层明文声明，并写入该次引用的审计记录。本母本锁定分段形式，不把 Δ 写成未经声明的常数。

三段为：

- 有序带：x < x_c − Δ
- 灰区相变带：x_c − Δ ≤ x ≤ x_c + Δ
- 混沌带：x > x_c + Δ

灰区隶属度：

μ(x) = 0，当 |x − x_c| > Δ

μ(x) = 1 − |x − x_c| / Δ，当 |x − x_c| ≤ Δ

μ(x) ∈ [0, 1]。μ = 1 只出现在 x = x_c。有序带与混沌带的隶属度都是 0；二者靠 x 与 x_c 的左右位置区分，不靠隶属度区分。

Δ ≤ 0 或 Δ 未声明时，三段式不得启用。此时只能报告 x 相对 x_c 的位置，不得声称已经完成灰区分段。

## 3. A3：「不妄觉·可证伪」诚实原则

凡称为觉察、识别、判别、检出的陈述，必须带有可证伪条件：指出何种观测、何种反例、何种复算会推翻该陈述。

没有证伪条件的觉察陈述，不得写入可引用结论，只能标为未完成索引。模型输出、可视化与事后解释，都不自动构成觉察。

## 4. A4：「不妄终·可审计」终局诚实原则

凡称为终局、终裁、收官、闭环完成的陈述，必须带有审计痕迹：输入标识、所用卷宗路径、版本号、指标 x、分段结果、仲裁记录与正文哈希。

缺任何一项，不得使用终局用语。050 作为系列终章，只终章于 001–050 的正文封存；它不把本母本宣称为不可再审计的终点。

## 5. A5：MAC 多仲裁体共识机制原则

MAC（Multi-Arbiter Consensus，多仲裁体共识）是灰区带与混沌带的收口机制。仲裁体至少包括该卷的哲学、工程、验证、规范四层。社会技术协议层启用时，人类权责席位加入仲裁体，见 A10、A11。

单一层不得单独给出终裁。共识记录至少写明：参与层、分歧点、保留意见、结论所依据的 x 与分段。未形成记录的一致，不算共识。

有序带可以按该卷自身规范直接给出可引用结论，仍须满足 A3 与 A4。灰区带与混沌带没有 MAC 记录时，结论停在「未终裁」。

## 6. A6：Corr₃D 三维非线性相关性矩阵原则

Corr₃D 是报告形式，不是一组已拟合的普适常数。相关性按三个轴记录，轴与轴之间允许非线性，不得压成一个总相关数后再丢弃分量。

三个轴为：

1. 层内：同一层内部陈述之间的一致与冲突
2. 跨层：哲学、工程、验证、规范之间的一致与冲突
3. 跨卷：被引用卷与引用卷之间的一致与冲突

报告时给出 3×3 的关系槽位。槽位没有观测时写「未测」，不得填 0 冒充独立。非线性只表示槽位之间不必服从一条直线关系；它不授权未公开的拟合函数。

## 7. A7：跨卷 / 二阶归一化耦合 Loss 架构原则

一卷的一阶损失用该卷验证层已有定义，并归一化到 [0, 1]，以便与 x_c 比较。第一纪元的四层合成见 A9。

跨卷耦合是二阶项。对卷 i，及其在 A8 的有向图中被明确引用的邻卷集合 N(i)：

L_i^(2) = Z( L_i^(1) + Σ_{j ∈ N(i)} κ_ij · ρ(L_i^(1), L_j^(1)) )

Z 把括号内的量映回 [0, 1]。ρ 是 A6 跨卷轴上已声明的相关。κ_ij 必须逐条声明。没有声明时，该 κ_ij 记为未启用，二阶项不参与分段；不得把未启用写成实测为 0。

二阶损失一旦启用，分段改用 L_i^(2) 作为 x。启用与否写入审计记录。

## 9. A9：四层谱系权重范式，第一纪元

第一纪元四层权重锁定为：哲学 30，工程 20，验证 25，规范 25。四点相加为 100。

L^(1) = 0.30 L_哲学 + 0.20 L_工程 + 0.25 L_验证 + 0.25 L_规范

四个分量都已归一化到 [0, 1]。缺任何一层，不得计算 L^(1)，也不得把缺层的权重摊给其余三层。

这组权重只属于第一纪元。改变权重必须更换版本号，并保留本文件的原哈希。不得在本文件内直接改数字。

## 10. A10：社会技术协议层 STPL 的启用条件与制式原则

STPL（Socio-Technical Protocol Layer，社会技术协议层）不是第五层正文，也不另占案例序号。它是高权责输出上的协议开关。

同时满足以下三条才启用：

1. x 落入灰区带或混沌带
2. 场景属于高权责：医疗、金融、司法、政务、工业安全、自动驾驶
3. 该输出将被当作可采信结论引用，而不是草稿、索引或未完成计算

三条缺一，STPL 保持关闭。关闭不是豁免。关闭时仍须按 A3、A4 说话，只是不套用 STPL 的人类权责席位。

制式：STPL 启用后，MAC 必须包含人类权责席位。模型侧四层可以给出分段与论据，不可以替代该席位的复核。高权责场景下，混沌带禁止把模型输出写成确定性终裁。

## 11. STPL 强制标记规则

引用本母本版本的输出，无论 STPL 开或关，都带标记。标记缺省不等于通过。

标记字段：

- STPL：on 或 off
- canonical：CANONICAL-v3.2
- volume：卷号；若只引用母本，写 050.5
- band：ordered、gray 或 chaotic；Δ 未声明时写 unsegmented
- x：所用归一化指标；未计算时写 uncomputed
- mac：共识记录标识；没有则写 absent
- human：required 或 not-required
- cite：所引文件路径及其 SHA256

STPL=on 时，human 必须为 required，且 mac 不得为 absent。标记与正文哈希不一致时，该标记无效。
