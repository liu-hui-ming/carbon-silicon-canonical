## 1｜为什么要有这份载体

自查表第 6 条要求 pending 项附「登记时刻＋二选一标注」；第 9 条要求报告附「样本清单」。这两条在现有台账里**无法满足**，原因不是执行不力，而是既有台账只记「哪一轮提到过」，不记「哪一刻第一次入账」，也没有二选一字段。

没有载体 → M1 无起算点 → 合格样本恒为 0 → 元裁定第一条规则自我卡死。

本文件只解决「有没有地方可以按字段登记」，不解决「登记时刻从哪来」。「登记时刻取自何处」属于证据来源问题，见 §6 已知限制。

## 2｜字段定义（六个必填 ＋ 四个可选）

### 2.1 必填字段

| # | 字段名 | 取值 | 说明 |
|---|---|---|---|
| F1 | `登记时刻` | ISO 8601 带时区（如 `2026-10-24T11:58:00+08:00`） | M1 起算点（RUL 2.1）。**必须由登记动作当场写盘**，不得事后回填推测值 |
| F2 | `来源HB编号` | `HB-nnnn` / `HR-nnnn` / `NONE` | 首次登记发生的那一轮。`NONE` 表示非轮次触发 |
| F3 | `事项描述` | 一句话，不写归因 | 只描述「什么待裁」，不描述「为什么」 |
| F4 | `分类` | `PREEXISTING_SUSPECTED` / `NEWLY_EMERGED` / `INCOMPLETE` | 二选一为口径要求；取不到翻转点时必须填 `INCOMPLETE`，**不得留空、不得填第三类名目以外的值** |
| F5 | `当前状态` | `OPEN` / `RULED` / `CLOSED` | `RULED` = 裁定已落盘并有实测哈希；`CLOSED` = 已移除 |

## 4｜登记纪律

1. **append-only**：已登记行不回改；状态变化另起新行并在 F6 写明「承接第 N 行」。
2. **分类判定责任**：`PREEXISTING_SUSPECTED` 与 `NEWLY_EMERGED` 的判定须有一句依据，写入 F6；无依据不得判，填 `INCOMPLETE`。
3. **不预设门禁**：填不全的记录标记为 `INCOMPLETE`，不会被系统拒绝；漏登的后果是「不出现在样本里」，不是「登记被拒」。**本文件不是门禁，不主张拦截能力。**
4. **与既有台账的关系**：本文件不改写任何既有条目；既有编号的权威状态仍以其原档为准，本文件只提供「可计量视图」。

## 5｜M1／M2 可计算性判定规则

一条记录只有在满足下列条件时才能计入 M1：

- F1 为具体时刻（非 `UNKNOWN`、非推测值）
- F4 为 `PREEXISTING_SUSPECTED` 或 `NEWLY_EMERGED`（`INCOMPLETE` 不计入，也不按任一类折中统计）
- 存在裁定落盘时刻 + 裁定文书路径 + 实测哈希

计入 M2 另需：合规移除时刻、F9 移除原因、F10 执行证据，且满足时序约束。

**不满足者不得以任何方式被汇总成平均值、比率或趋势。**

## 6｜已知限制（起草时自陈，不掩饰）

1. **「登记时刻」的历史值不可得。** 既有 pending 项在合并入本表时，F1 只能取「合并动作时刻」，而非「原始入账时刻」。若如此，必须显式标注 `F1=并入时刻`，且**该条不得计入 M1 历史样本**——否则会把「我刚建表」伪造成「刚登记」。
2. **F4 对历史项多为推断。** 对已存在数日的条目，「是否老缺陷」通常只能推断。推断值须标 `_INFERRED`，且不计入需要精确分类的统计。
3. **本文件不产生证据。** 它只整理与管理证据；若原始台账没有登记时刻，本表写得再全也不会凭空生成一个。
4. **本文件不是门禁。** 无拦截实现、无强制校验。填错能落盘，漏填也能落盘。
