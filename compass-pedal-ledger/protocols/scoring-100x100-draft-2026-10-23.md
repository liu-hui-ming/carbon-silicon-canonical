## 一、概念基础层（置顶，不可省）

```
分数      对指定对象、指定协议下的评价           → 快照，可保留
证据资格   现有材料支持多强的结论               → 决定结论能走多远
独立性     执行者/实现路径/复核过程的独立程度    → 决定验证的证明力
```

三者不可相互替代，**必须分别记录**。

界分示例（HB-0964）：91 分是分数；`AUDIT_PENDING` 是证据资格；文本审阅≠独立验收是独立性。三者曾混在一份暂评里。

**封顶是分数的天花板，不是独立性的替代品。**
同一函数反复复算得到一致结果，只增强对计算一致性的信心，不能凭重复次数产生独立复现。独立实现、独立复核、未见样本迁移，三者必须分别证明。

## 二、双层刻度（100 + 100）

| 层 | 名称 | 内容 |
|---|---|---|
| 第一层 | 简报与审计质量 | 证据组织、口径边界、假设质量、自检纠错、可追溯性（沿用原 100 分表，不改写旧表） |
| 第二层 | 方法验证能力 | 新增独立 100 分，见下 |

第二层配分：

| 指标 | 分值 | 核心问题 |
|---|---|---|
| 自我证伪能力 | 25 | 是否预先说明什么证据会推翻自己的判断？ |
| 独立复现能力 | 25 | 不依赖原作者实现，能否得到一致结果？ |
| 跨样本迁移能力 | 20 | 面对未见样本，规则是否仍有效？ |
| 比较前预测能力 | 15 | 是否在看见结果前留下可核验的预测？ |
| 纠错闭环效用 | 15 | 纠错是否实际减少错误，而不只是补齐记录？ |

两层**分别报告**，不以总分掩盖方法验证缺口。总分仅在协议授权且计算条件满足时报告。

## 三、三档封顶（嵌套上限，取最严，不累加）

| 封顶 | 触发缺失 | 第二层上限 | 最低证据 |
|---|---|---|---|
| A | 合格独立复现 | ≤ 80 | 复现者身份 + 对应输入与协议版本 + 独立执行记录 + 输出差异及解释。仅作者自算或原报告声称“复算一致”不够 |
| B | 预先界定的未见样本测试 | ≤ 60 | 测试前冻结样本选择规则/判定标准/协议版本 + 样本未参与规则制定或调参的证据 + 失败案例报告。仅换文件名或重复原样本不够 |
| C | 比较前预测 + 纠错实效 | ≤ 40 | 带时间戳的预先预测 + 可核对结果 + 误差判据 + 修正前后对照。仅有预测文本、勘误记录或“已修复”声明不够 |

封顶是上限，不是自动给分。缺证据应标 `UNKNOWN` 或待评，不得把未知当通过。

## 四、评分主体三类（待审议）

| 主体 | 允许用途 | 限制 |
|---|---|---|
| 简报作者自评 | 初步自评与证据索引 | 第二层不计入正式总分；试算须明标自评 |
| 非作者复核者 | 审核证据、提出反例、评定第二层 | 须披露利益关系、方法依赖、复核范围 |
| 独立实现者 | 按同一协议独立实现并复现 | 独立实现 ≠ 独立复核，也不自动证明跨样本有效 |

不采用“作者自评整体封顶 40”作为解法：封顶限制分数，不能让缺乏独立性的结果变成独立证据。

### 案例③ 待审议三问（主体不合格时）

```
① 哪些利益关系 / 方法依赖足以构成主体不合格？（判定标准）
② 主体不合格时，能否提供不计入正式成绩的试算？（处置选项）
   候选：拒绝正式评分、仅留自评档 ／ 允许受限试算分
③ 谁复核主体资格判定本身？复核者的资格如何确定？（二阶边界）
```

第③问是递归边界：只规定谁有资格评分、不规定谁审资格判定，资格审核即成为不可外部检验的自证环节。

## 五、方法验证四层（不同问题，非自动递进阶梯）

```
L1 单例复算吻合     指定样本结果一致
L2 样本集规则复现   既有端点族全样本按【预先冻结规则】得预期结果
L3 契约明确         字节端点 / 哈希端点 / 尾随换行具可执行定义
L4 独立验收         符合预设资格者检查证据并独立形成结论
```

禁止 L1 直接声称 L4。四级不必然线性：契约定义、样本复现与独立验收回答不同问题，各级进入条件与依赖关系须事先定义。
正样本的累积数量不能自动升级为规则级结论。

## 六、元评分自检（评分制须受自身检验）

三类预定义失败案例（故障注入）：

| 用例 | 预期识别行为 | 关键验收点 |
|---|---|---|
| ① 文档优秀、方法不可独立复现 | 触发封顶 A（≤80） | 不得以文档质量代替复现证据 |
| ② 复现成功、未见样本失败或缺失 | 触发封顶 B（≤60） | 不得把复现成功当成迁移成功 |
| ③ 各分看似合格、评分者缺乏独立性 | 主体规则拦截 + 封顶 C（≤40） | 不得以分数折扣替代独立性审查 |

三项验收检查：规则是否事先冻结／输入证据是否符合预设／结果是否按规则输出／是否临时改规则。
三例各自通过 ≠ 评分制度已被充分验证。

**防循环条款**：不能用双层评分制自身给出的高分，证明双层评分制有效。评分制度本身亦需预先定义的测试、外部复核与失败判据。

## 八、评分纪律（不得追溯改写）

- 旧评分冻结于其评价时点与对象。后续事件进入**新审阅记录**，注明新增证据、协议版本、判定时刻。
- 不因新事件把旧分改成另一个分；若重评，另立记录。
- `AUDIT_PENDING` 不等于内容必然错误；`哈希匹配` 不等于来源完整；`复核成功` 不等于程序验收。
- 试行起步：先 200 分制，经受独立复现与未见样本测试后，再议是否扩到 400/800。

## 勘误 03｜三层审查点与索引（2026-10-23 08:34 追加，原文件不覆写）

### 审查点一：跨层引用必须记录证明命题

```
同一份复现记录可被第二层（方法验证）与第四层（治理与审计）引用，

禁止：因引用相同而自动双计分
```
