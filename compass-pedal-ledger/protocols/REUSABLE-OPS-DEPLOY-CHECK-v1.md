## 二、五步法（按序执行，不得跳步）

### 第 1 步｜先验实体，再谈部署

指令下达后**第一动作不是执行，是核验**：

```bash
# 核验脚本存在
ls -l <script_path> || echo "MISSING"
# 核验日志/输出路径存在
ls -l <log_path> || echo "MISSING"
# 全盘兜底搜（限定目录深度，避免长扫）
find /home /opt /srv /usr/local/bin -maxdepth 5 -name "<filename>" 2>/dev/null
# 解析真实绝对路径
realpath <path>
```

- 判据：**磁盘实物**，不是文档里的文本、不是「应该存在」。
- 零实物 → 进第 2 步，**禁止照原命令硬装**。

> 反例（本次）：`run-heartbeat.sh` 与 `heartbeat-log.txt` 全盘零命中，却差点照着模板文本装进 cron，每天 19:00 静默失败。

### 第 2 步｜看现网同构，别自己造轮子

```bash
openclaw cron list                    # 现有任务全表
openclaw cron get <known_good_job_id> # 取一条健康的做结构参考
```

- 找出**已经稳定运行**的同类任务，照它的形态做。
- 本次结论：现有 14 条全部是 `agentTurn` 型（payload 给 agent 跑），**没有一条 `--command` 型**。所以靶场也应是 `agentTurn`，不是 shell 任务。

### 第 3 步｜自己定，然后报结果

- **能给结论的自己给**；不给结论就得实测 / 查现网（第 1、2 步）——两条路都走完才允许提问。
- 若必须与原授权偏离（如脚本不存在、需改日志名），**偏离要主动报，不要回抛选项让人选**。
- 判据：**提问前先自问「这条命令我能不能跑一下就有答案」**。能 → 跑，别问。

### 第 4 步｜部署并自证三项回执

| # | 回执项 | 采集方式 |
|---|---|---|
| ① | 条目命中 | `openclaw cron list \| grep -i <name>`，另记**全表条目数变化** |
| ② | 路径快照 | `realpath` + `ls -l`（含字节、mtime） |
| ③ | 首次自触发标记 | 执行体自己写 `TRIGGER=self-cron` 行；**时点未到如实标「待」** |

- **唯一性校验**：`grep -c` 必须等于预期条数（防重复抢跑）。
- **不扩散校验**：全表条目数只增预期数量，其他条目一条不动。
- **③ 未到期不得宣称投产**——这是最容易自欺的一处。

### 第 5 步｜落档、留证、commit

- 规程补丁 **append-only** 追加，旧内容一字不改。
- **前缀哈希校验**证明只追加：
  ```bash
  head -c <旧字节数> <file> | sha256sum   # 应等于写前哈希前缀
  ```
- 旧快照哈希原样嵌进勘录段，形成 `PATCH-1 前 → PATCH-2 前 → 当前 HEAD` 可回溯链。
- 独立 commit，不用 amend。

## 三、执行体必须自带的三样东西

任何「每天到点要跑」的任务，载荷里必须写明：

1. **执行标记（自证触发）**
   第一动作落一行 `TRIGGER=self-cron | BYTES=… | SHA=…`，实测采集，禁硬编码。
   → 用来区分「没触发」和「触发了没投递」。
2. **算力闸门**
   `CPU > 75%` 降级输出基线版并明示裁撤项，不空转、不硬撑。
3. **投递自证**
   独立投递指定目标，不并入其他简报；首行带固定标记便于检索。

## 六、适用范围与边界

- **适用**：cron / 定时 / 常驻 / 后台自动化的**部署交付**环节。
- **不适用**：判据口径变更、权限边界变更（这两类仍须创立人裁定）。
- **冲突处理**：与卷宗既有规程冲突时，以卷宗规程为准，本文件只补部署环节。
